2026-11-11 定的办法：先用行为定三个瞬间（一眼看全、拆包、进门），每个先做一个能动的样机，在手机上按手感过门，三个都过了再选外观。三个瞬间 2026-11-13 都过了门，外观同日定旧书房，现在按门把它做到成品（见下一节）。样机是独立页面，不进 `build.py`，不碰主站代码；推到 main 以后就能打开（主站的离线缓存不管这个目录）。

## 外观：旧书房（2026-11-13 用户定）

选的办法：不看静态图定，把三个候选（纸模、玩具盒、旧书房）做进过了门的样机，用户在手机上换着看，答「旧书房」。当时的对照图是 `docs/lab-looks.jpg`。

旧书房是什么：暗处一盏暖灯；胡桃木的架子带压顶线和底座；读过的书是布面烫金、三道竹节，没读的包着牛皮纸捆两道麻绳，在读的探出来带一枚亮签；拆包那一页是胡桃木桌面上一盏灯，包是牛皮纸捆两道麻绳、贴一张签、盖一枚邮戳，牌背是藏青布面烫金，牌面是米色的纸。「没读的书」和「没拆的包」是同一种东西。三个瞬间现在的样子见 `docs/lab-study.jpg`。

外观都在 `kit.js` 的外观表 `LOOKS` 里：一种外观管背景与光、架子的颜色和厚薄、书的颜色与书脊的画法、在读那枚签、网页上那层字和按钮的颜色、进门页最下面一层的摆设（`props`）、拆包页的桌面与包和牌（`pk`）。

| 外观 | 现在的地位 |
|---|---|
| 旧书房 `study` | 选定的方向。没选过的设备打开就是它 |
| 灰盒 `grey` | 三个瞬间过门时的占位样子，留着对照。顶栏「外观」按钮里能换，换过记在设备上，三页一起换；地址加 `?look=grey` 也行 |

不要动的：读没读的区分（没读浅、读过深、在读探出带签，只靠明暗和形状），测试里量着明暗差。

### 2026-11-14 书架页这一轮

起因：用户 11-13 夜里发来手机上的照片，说了五件事。逐条对应：

| 用户说的 | 查到的原因 | 改了什么 |
|---|---|---|
| 书不清晰、发糊 | 书脊的字画在一张图上，每本固定 48×192 像素一格；四十本时一本书在三倍屏上有一百像素宽、四百多像素高，是放大三倍贴上去的。画布还封在两倍，三倍屏上再放大一倍半 | 书脊按书在屏上的大小画（四十本时一格 128×512，一百二十本 88×352，三百本按总面积封顶）；画布按屏幕真实像素出，最多三倍，连着一秒多跑不动就退到两倍、再退到一倍半，只退不进；书名的字放大到占书脊宽的七成、描粗一道 |
| 书发暗 | 没读的书脊在屏上的平均明度只有 .28，读过的 .07 | 天光 1.05 → 1.35，主光 3.5 → 4.7；灯光圈外面从暗到一半改成暗到七成；角落的暗从 .9 减到 .68；网页那层暗角从 .4 减到 .2、颗粒从 .035 减到 .02；没读的纸色略浅，上面的字从浅褐改成深褐。量过：没读的 .28 → .37，读过的 .07 → .15（字大了、金色亮了），整屏 .074 → .103 |
| 上面下面的字和按钮挤占书架 | 顶栏（拆包、进门、声音、外观）和底栏（两行字、排法、本数）一直摆在屏幕上，架子四周给它们让了两百来像素 | 屏幕上只有书架。这些东西收进底下一张工具纸，平时只留一道小把手（点它，或者按住往上划）；点纸外面收回去。架子用整屏排，四十本从三层变四层 |
| 读没读要不要手标 | 原来抽出一本后底下是「没读 / 在读 / 读过」三个按钮 | 不用手标：底下是「打开读」，读了一点（样机里头一下算百分之二）自己变成在读、包书纸拆掉露出布面，读完自己变成读过；一条细线显示读到哪。只留两行小字给补标：「在别处读完了」「当作没读过」。样机里没有阅读器，点一下「打开读」算读了一段 |
| 在读的白签有没有更好的选择 | 白签在书顶上，像一本更高的书，又是屏幕上最亮的一块 | 多做了一种「丝带」：书脚下垂一条书签带，搭过层板的前沿，尾巴剪成燕尾；现在默认是它，工具纸里能换回白签对比，选哪种记在设备上（地址加 `?mark=tab` 也行） |

三件家具之间怎么换（用户说左右按钮或左右滑，让 Claude 定）：定成底下一排三个小记号，点哪个去哪个，在这一排上左右划也行；不做整屏左右滑，因为手指在书脊上左右划已经是「划过书脊」了，两个手势会打架。等档案架做出来时一起上，现在只有一件家具，不放空的记号。

没做的和没验证的：

- 真机上没看过。画布提到三倍以后要画的像素是原来的两倍多，帧率够不够只能真机说，跑不动会自己退。
- 进门页只把书脊的格子从 192 提到 256，画布还封在两倍、顶栏底栏没动；拆包页没动（它的光是自己的一套，只有暗角和颗粒跟着轻了）。
- 丝带是平的一条、自己发一点光，没有做缎面的反光和褶；三百本时只有两三个像素宽。
- `docs/lab-study.jpg` 里书架的几格是 11-13 的样子，这一轮的前后对比在 `docs/lab-shelf-clear.jpg`。
- 软件渲染下每帧耗时：一百二十本 146 → 156 毫秒（架子占的屏幕大了）。

请用户在手机上留意：

1. 书名看着清不清楚，整面亮度够不够；最下面一层呢。
2. 屏幕上只有书架，这样对不对；底下那道小把手找不找得到、碍不碍眼。
3. 丝带和白签（工具纸里换），哪种一眼认得出是在读的。
4. 抽一本没读的点「打开读」，它自己变成在读，这样对不对；补标的两行小字要不要。

门 2 的实情（2026-11-13）：

- 尺寸怎么来的：没有下载参考照片，按文字资料里的比例和这个项目 11-06 做拱形书柜时的量尺办法定（都记在 `REFERENCES.md`）。压顶线三段大小相近（凹弧、平带、反曲线），原大高 5.9 出 4.6 厘米，为了给书多留地方缩到七成五；底座高 8 厘米，立面上面收一道反曲线；壁柱比侧板往外宽 1 厘米、往前凸 1 厘米；层板前沿是半圆。书的封面板厚 2.5 毫米、飘口 3 毫米（装订的常规是 2 到 3 毫米）；圆脊鼓出书厚的 0.22（印厂资料说常见是 130 度的弧，约 0.32，照那样厚书会伸出层板，所以取浅一点）。**真书房的照片并排对形这一步没做**，要做得先下载几张公版照片，等用户点头。

## 拆包（`index.html` + `pack.js`）

一包没拆的剪报从上面送到眼前，沿封口横着划开，五张牌背朝上落到桌上，一张张点开，翻开的再点一下拿到眼前看，最后向上划或点「收下」，下一包送到。右上角是声音开关和「外观」。这一页只做了旧书房和灰盒两种外观（写在 `index.html` 的 `<html data-looks>` 上）。

开法：2026-11-12 用户在手机上试过，定「热闹」（顿帧、闪光、火星、镜头一震）。「安静」那一套参数还留在 `pack.js` 开头的 `MODES` 表里备查，地址加 `?mode=quiet` 才进；系统开了「减少动态效果」的设备默认走安静。

还可以接着调的（用户没提就先不动）：划开跟不跟手、一格一格的声音和震动；发牌的快慢、「全部翻开」够不够；牌底光晕（越亮这篇越长）；拆到第三包、第五包还想不想拆。

## 一眼看全（`shelf.html` + `shelf.js`）

一座立体的书架，多少本书都整座装进一屏（本数多了架子自己加宽加层）。读没读只靠物件的样子说，不靠颜色、不贴标签：没读的包着白纸（浅），读过的露出本来的布面（深），在读的探出来一截、脚下垂一条丝带（或者顶上露一枚签，工具纸里换）。

2026-11-14 起屏幕上只有书架：排法、在读的记号、本数、声音、外观、去拆包和进门的链接都在底下的工具纸里，点最底下那道小把手（或者按住往上划）才出来。不带参数打开是四十本（用户自己的书是三十八本）。

1. 上架：书一本本从外面推进去，镜头同时往后退到看全；点一下屏幕快进。
2. 划过：手指按在书脊上划，碰到哪本哪本探头，一本一声一震（越厚的书声音越低），手指上方的小签报书名。电脑上鼠标移过去就探头。
3. 抽出：松手，那本滑出来、转过封面飞到眼前；左右拖动转着看；底下是「打开读」和一条读到哪的细线，读没读跟着进度自己变（2026-11-14 前是「没读 / 在读 / 读过」三个按钮手标）。
4. 放回：点「放回去」或点空白处，飞回去、推进去一声闷响。
5. 换排法（工具纸里）：「按类放 / 按读没读放」，整面书一起飞到新位置；按读没读放时，层板边上有小签写每组多少本，改过状态的书放回去会站到新的一组。
6. 换本数（工具纸里）：40 / 120 / 300，看到多少本开始觉得看不全。

2026-11-12 用户上手后答「过」。当时请用户留意的几件事（留作记录）：

1. 进来那一眼，不看底下那行字，能不能说出读过大概几成。浅和深的差别够不够。
2. 40、120、300 本，到多少本开始觉得太密、看不全。
3. 手指划过书脊，探头跟不跟手，一本一声对不对，小签挡不挡视线。
4. 松手就抽出，会不会老是误抽；抽出和放回的快慢。
5. 两种排法哪种是平时想看的；换排法那一下是痛快还是乱。
6. 改了读没读以后书架跟着变（变深、探出来、挪位置），有没有「这面墙是我读出来的」的感觉。

手感的强弱都在 `shelf.js` 开头的 `P` 一张表里（上架多久、探出多少、抽出与放回的时长、换排法绕多远、镜头晃多少）。书名和作者是编的，没有接真实书目，改的状态不保存，刷新就回到原样。

## 进门（`door.html` + `door.js`）

点开别人的链接，三秒看懂他在学什么，一个动作带走一排。人名、那句话、书名都是编的。

进法：2026-11-12 用户在手机上两种都试过，定「直接到」，不要敲门那一段。「敲门进」（一扇门、门牌、敲两下、门开、镜头穿过门，约 2.4 秒）留在 `door.js` 里对照用，地址加 `?way=knock` 才走，页面上不再有切换。

1. 到：点开链接，书架直接在眼前；屏幕顶上是「谁的书房」和他自己写的一句话。约一秒就能动。
2. 看懂：一座书架，一排一个科目。层板边上的签一枚枚冒出来（科目、多少本、读过多少），那一排书跟着抖一下。读没读和书架样机同一套：浅的没读、深的读过、探出来带签的在读。最下面一层是他的牌盒和本子，样机里只是摆着。
3. 看书名：手指按在书脊上左右划，碰到哪本哪本探头、报书名；只是看，不抽出来。
4. 带走一排：按住一排往下拉，这一排的一份（包着白纸，到你手里都是没读的）跟着手指一本本从架上出来，一本一声一震；拉到底就带走，过了六成松手也带走，没到就弹回去。捆成一捆飞进底下的邮包，他的书还在架上。层板上那枚签点一下，也是带走这一排。
5. 邮包：点开看带走了什么，可以倒回去重来。底下「再进一次」可以反复看到的那一下。

上手时请留意的几件事：

1. 从点开到看懂他在学什么，够不够快。顶上那句话加四排的签，是不是就够了，还缺什么。
2. 进法：已定「直接到」（2026-11-12）。
3. 往下拉带走：跟不跟手，一本一声对不对，六成这个线松手带走是太容易还是太难。
4. 往下拉和左右划会不会互相误触。
5. 拉着带走和点签带走，你实际会用哪个。
6. 带走的是一份白纸包着的、他的书还在架上，这个意思看不看得出来。

节拍和强弱都在 `door.js` 开头的 `P` 一张表里（签什么时候开始冒、一枚隔多久，往下拉多少算到底，过几成松手带走，收拢和飞多久；敲门进的四行只有 `?way=knock` 用）。样机里没有接真实的分享链接，牌盒和本子不能带走，带走的东西不保存。

## 技术

three.js 0.186（`vendor/three/`，自带）只画物件，字用网页排；外观表里的花纹（纸浆、布纹、木纹、护墙板）是页面打开时用画布现场画的小图；旧书房另有三张扫描的材质图在 `vendor/tex/`（木头两张、书布一张，转换脚本 `tools/tex/to_webp.py`）；声音是 WebAudio 现场合成的，没有音频文件；苹果手机没有震动。书架上的书是一个 InstancedMesh（三百本也只画两三次），书脊的字画在一张图集上；抽出来的那一本换成单独的模型；进门页里带走的那一份是同一批书的第二个 InstancedMesh，用一张全是白纸包的图集。地址加 `?dev` 显示帧率和状态（进门页还显示从点开到能动用了几秒），书架页加 `?n=300` 直接进三百本，进门页加 `?way=knock` 走留作对照的敲门进。
