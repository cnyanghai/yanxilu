# lab：能动的样机

2026-11-11 定的办法：先用行为定三个瞬间（一眼看全、拆包、进门），每个先做一个能动的样机，在手机上按手感过门，三个都过了再选外观。三个瞬间 2026-11-13 都过了门，外观同日定旧书房，现在按门把它做到成品（见下一节）。样机是独立页面，不进 `build.py`，不碰主站代码；推到 main 以后就能打开（主站的离线缓存不管这个目录）。

| 瞬间 | 页面 | 线上地址 | 状态 |
|---|---|---|---|
| 拆包 | `index.html` + `pack.js` | `/lab` | 2026-11-12 用户上手后定「热闹」 |
| 一眼看全 | `shelf.html` + `shelf.js` | `/lab/shelf.html` | 2026-11-12 用户上手后：过。2026-11-14 起这一页里有三件家具：书架、档案架（`?f=rack`）、笔记本架（`?f=notes`），底下一排记号换 |

公用的零件（动画轨、声音、舞台、书的样子、架子、外观表）在 `kit.js`，书架和进门两页共用；开牌盒以后牌怎么摆怎么动在 `box.js`、牌长什么样在 `card.js`（书架那一页用）；`pack.js` 是最早写的，动画和声音自带一份，颜色、光、桌面、包和牌的画法 2026-11-13 起也接到外观表上。

## 外观：旧书房（2026-11-13 用户定）

选的办法：不看静态图定，把三个候选（纸模、玩具盒、旧书房）做进过了门的样机，用户在手机上换着看，答「旧书房」。当时的对照图是 `docs/lab-looks.jpg`。

旧书房是什么：暗处一盏暖灯；胡桃木的架子带压顶线和底座；书各有各的布面颜色和款式（一类一个色系，2026-11-14 起，见下面「书的颜色和款式」），没读的书脚围着腰封，在读的探出来、脚下垂一条丝带；拆包那一页是胡桃木桌面上一盏灯，包是牛皮纸捆两道麻绳、贴一张签、盖一枚邮戳，牌背是藏青布面烫金，牌面是米色的纸。「没读的书」和「没拆的包」是同一种东西。三个瞬间现在的样子见 `docs/lab-study.jpg`。

外观都在 `kit.js` 的外观表 `LOOKS` 里：一种外观管背景与光、架子的颜色和厚薄、书的颜色与书脊的画法、在读那枚签、网页上那层字和按钮的颜色、进门页最下面一层的摆设（`props`）、拆包页的桌面与包和牌（`pk`）。

| 外观 | 现在的地位 |
|---|---|
| 旧书房 `study` | 选定的方向。没选过的设备打开就是它 |
| 灰盒 `grey` | 三个瞬间过门时的占位样子，留着对照。顶栏「外观」按钮里能换，换过记在设备上，三页一起换；地址加 `?look=grey` 也行 |

不要动的：读没读只靠明暗和形状说，不靠色相（用户红绿色弱）。旧书房 2026-11-14 起是「没读的腰封还在、读起来就摘了、在读的探出来垂丝带」，腰封是浅色的纸，比哪一种布面都亮，测试里在屏上量着这个明暗差；灰盒和两种落选的样张还是原来的「没读整本浅、读过整本深」。

### 2026-11-14 接上账号（立体书房 `#shufang`）

用户同日说牌的设计先保持这样（牌背、牌的效果以后做成能挑的东西放进商店），问接下来做什么，并以为本子打不开是因为登录没做。查到的实际情况：

- 登录是有的：主站 `/login`（手机号加密码，能注册、能找回密码），纸模版一直在用。
- 没接账号的是这几页样机：里面的书、牌盒、牌、本子全是代码编的，改过的读没读一刷新就没了。
- 本子打不开不是因为登录，是「翻开本子」这一步还没做。

所以把原来排在最后的「接真实的书和剪报」提到最前面：装盒、翻开本子都得落在真的内容上才有意义，真数据里的毛病（书名很长、只有两本本子、一盒只有两张牌）也该早一点看见。

**怎么接的。** 主站加了一页 `#shufang`，整屏一个 iframe 嵌着 `lab/shelf.html?host=1`。三维这一页自己不取数据、不认账号、不写任何记录：

- 要数据：`window.parent.YXL_ROOM.snap()`，主站用它自己原来那些函数算一张快照（`src/app.js` 的 `roomSnap`）。读没读、哪一盒有哪些牌、本子有几页，只有主站那一处算法，这边不抄一份。
- 要打开什么：`YXL_ROOM.open(kind, id)`（`roomOpen`），往哪去是主站定的，回来告诉这边是阅读器盖在上面（`"reader"`，这边停下不画）、换了页（`"page"`，这一页被拿掉）还是开了新标签页（`"tab"`）。
- 主站的记录变了（读完一篇、别的设备上加了书），主站叫 `__lab.sync()`，这边比一下快照，有变化才动：手里正拿着一本书、开着一盒牌的时候只改这一件自己的读没读，整批等回到看全再换，不带上架那一段。
- iframe 挂在 `body` 上，不放进 `#main`：主站的 `render()` 每次都重写 `#main`，放进去会把三维那一页重载。
- 单独打开 `lab/shelf.html`（没有 `?host`）还是样品，工具纸里多一行「进我的书房」。五条样机测试走的还是样品。

**快照里有什么**（`shelf.js` 的 `fromHost` 把它换成架上的东西）：

| | 字段 | 说明 |
|---|---|---|
| 书 | `id title by cat st prog eb page` | 和纸模版书墙同一批（书单里的加自己放的）；`st` 是没读 / 在读 / 读过；`eb` 挂没挂电子书，`page` 有没有书页 |
| 牌盒 | `id title cat vol glyph cards[]` | 和纸模版档案架同一批、同一个顺序；每个领域没装盒又拆过的剪报算一盒「散页」 |
| 牌 | `id title src why whyLab min mark foot mon day no read kind` | 一篇剪报或者一件自己的档案。写了为什么存的印那一句，没写的印开头几句（小字标「开头几句」）；外链和档案没有分钟数，圈里换成一个字 |
| 邮包 | `id title cat n` | 每个领域还没拆的剪报算一包 |
| 本子 | `id title cat pages kindName ago` | 随手本加主题本；`ago` 是几天前写过，没写过是 -1 |

书有多厚多高主站不知道（没有页数），按书的 id 定一个，同一本书永远一个样；底下那行字不写页数。类别是用户自己的领域，名字直接用，颜色按顺序轮六个色系（超过六个会重）。

**手上的变化**（只在嵌进主站时有）：

- 抽出来的书、本子、邮包，再点它一下就进去，和牌盒一样点物件本身。书：挂了电子书的开阅读器，书单里有书页的去书页，都没有的去纸模版的书架（那本的书立开着，能挂电子书）。本子：去纸模版的本子页，在那里写。邮包：去纸模版的档案架，那一袋摆在桌上等着拆。
- 开着的牌盒里，立着的那张背面朝上点一下翻开；面朝上再点一下读全文（剪报开阅读器，外链和档案开新标签页）。
- 翻开看一眼牌面不算读过。读没读是在阅读器里读出来的，和纸模版一个算法；合上阅读器回到原处，那一张和盒面上的没读数跟着变。样品里「翻过来就算读了」的说法只留在样品里。
- 底下那张纸上「在别处读完了」「当作没读过」两行不出来（这一步不写记录）。
- 从别的页按返回：回到书房、回到刚才那一件家具前，上架那一段快进。不记得刚才抽出来的是哪一件。
- 工具纸里写着谁的书房；没登录时架上只有书单里的书，多一个「登录」（去主站的登录页，登录完回书房）；「纸模版」回到这一件家具的纸模页。

**没做的、知道的毛病：**

- 真机上没看过。真账号里的书和牌我看不到，只在测试账号（一本书、一盒四张牌、两本本子）上走过。
- 主站上没有入口，只有地址 `#shufang`；纸模版还是首页。要不要把书房当首页、入口放哪，等用户看过再定。
- 东西少的时候架子很小、屏幕空着一大半（两本本子、三四个盒）。

### 2026-11-14 用户看过真数据后的一轮

用户登录后在手机上看了书房，提了四件事。对比图 `docs/lab-room-fix.jpg`（上排：档案架、笔记本架改前改后；下排：从书房打开的本子页、拆包页、档案架页）。

**一 东西少的时候像一个小盒子、很空。** 原因：架子最窄三十六厘米，只有三四件东西时里面空着一大半，镜头照着架子的宽取景，东西在屏上就很小（一个牌盒不到二十像素宽）。改法（`shelf.js` 的 `chooseW`）：架子最窄可以到刚好放下最宽的那一件，件数少的时候架子跟着缩、层数跟着屏幕的形状分（竖屏会分成两三层），镜头跟着靠近。四件东西的档案架现在是两层两列、占满一屏，一个盒五十多像素宽。没有往架子上加摆设凑数：这座架子的用处是一眼知道有多少东西，摆假的会看错。看这件事有个调试参数：样品页加 `?few=3` 每件家具只留三件。

**三、四 邮包和本子点进去成了以前的墓园主题。** 原因：墓园宽柜是主站「布置」里的一个场景，选了以后记在这台设备上；「布置」的入口 2026-11-09 就拿掉了，以前选过的设备换不回来。改法：主站不再认这个场景（`src/app.js` 的 `lookGet`；独立入口 `youchai/` 冻结着不动）。另外，从书房走出来的这几页（本子页、书架、档案架）换成旧书房的颜色：只换纸模那一套变量（`src/page.html` 的 `html.room-skin`），版面、材质、字不动，底是深胡桃木、面是旧纸（和牌面同一个纸色）、品牌与主操作是枣红、没选中的砖是藏青，选中没选中仍然靠明暗。直接打开纸模页（不经过书房）还是原来的牛皮纸；阅读器不跟着变。这几页底下多一枚「回书房」（手机装成 App 时没有返回键；拆包的桌面开着时不出，免得挡字）。

没做的：东西只有一两件时架子还是只有一层、上下留着墙和地；书的款式、本子的页面本身没有重新设计，只是换了颜色；真机没看过。

### 2026-11-14 开牌盒（同日第二版：扇形）

起因：三件家具上线后用户答「整体可以」，问下一步做什么。Claude 定的顺序：开牌盒 → 拆完的牌装进盒子 → 翻开本子 → 再过一次门、接真实的书和剪报。先做开牌盒，是因为档案架上的牌盒只能看不能开，而且「开盒」是一个新的瞬间，手感要先做对。

第一版（同日上午上线）是抽出盒子点「打开」，牌叠着摊成一两列，每张露出顶上一条标题，划过、松手拿到眼前、放回。用户试过以后说了两件事，让 Claude 想一下：

1. 抽出来的盒子不用点「打开」，再点它一下就该开。
2. 他原来想的不是竖着两列，是一个大圆的扇形，来回左右翻着看；像炉石开卡包，五张围成一圈。牌少可以那样，牌多就做成大圆的扇形。

Claude 的判断：扇形更合适，当天改了。理由和代价：

- 左右划是这一页已经在用的手势（划过书脊、换家具），一只拇指就够；两列要上下找。
- 第一版自己记过的毛病是牌多的时候每条只露十七到二十来个像素，标题挤在里面。扇形里每条三十多像素宽，字也大一点（十六 → 十八像素）。
- 牌是斜着压着的一把，比两列平铺更像手里的东西，合「立体做到物件一层」的方向。
- 代价：一屏看不全了，手机竖屏一次看得清九条上下的标题（第一版是全部）。补救是没读的还是排在一头、一打开就停在头一张没读的上，底下写着第几张、共几张；两头挤成一沓边，看得出还有。
- 炉石那两样里，学的是「手里那一把牌」（排成弧、碰到的那张立起来放大），没有学「五张围成一圈」：围成一圈是开包时揭晓用的，那一下我们在拆包页已经有了；竖屏上围一圈每张只有一百来像素宽，比扇形还小。牌只有两三张的时候，是同一把扇子错开得大一点、每张露出大半张。

回答一件事：一盒几十张牌，怎么翻着看、一下找到想看的那张、看完合上。牌在 `box.js`，由 `shelf.js` 叫。新旧对比在 `docs/lab-fan.jpg`（最左一格是第一版）。

1. 打开：在档案架上抽出一个牌盒，底下那行字写着「再点一下盒子打开」。点盒子，它缩小落到屏幕底下、盒口朝着人，盒盖往后掀开，牌一张张飞出来。点在盒子外面是放回去；键盘上回车也能开。
2. 成扇：牌排在一个大圆的弧上（圆心在屏幕正下方很远），跟着弧歪，后一张压着前一张，每张露出左边一条，标题竖着写在这一条上。没读的背面朝上（牌背是老书的烫金封面，见上面「牌的样子」），在扇子的右头；一打开就停在头一张没读的上。
3. 立起来：转到正中的那张从扇子里抽出来、放大，停在扇子上面给人看（正面写编号、来处、日子、为什么存它、读完要多久）；它两边的牌往中间合拢。底下只剩一行字（第几张、几张没读）和「合上」。
4. 转：手指按着左右划，整把扇子跟着转，一张一声一震，越往右声音越高；松手顺着速度再滑一点，停在最近的一张上。转得快的时候正中那张只探一点头，停下来才立起来。点扇面上露着的任何一条，直接转到那一张。鼠标滚轮、键盘左右箭头也能转。
5. 翻开：立着的那张要是背面朝上，点它一下翻过来，翻过来就算读了（键盘回车也行）。读过的再点没有反应（正文还没接）。
6. 合上：点「合上」或者点底下的盒子，牌一张张回盒里，盒盖合上，盒子回到眼前；盒面上「几张没读」跟着变，放回架上以后，都读过了的盒子顶上那枚签就没有了。

几个取舍：

- 标题为什么竖着写在左边：扇面上后一张压着前一张，露出来的只有左边一条；竖排和书脊是同一种读法。所以牌面重排了：左边四分之一是竖排标题，一道细线，右边是别的。竖排时冒号、破折号、括号躺倒，逗号、顿号挪到右上角；太长先缩字再截断。
- 为什么不要「拿起来」那一步了：第一版叠着的时候只看得到标题，要拿到眼前才看得到整张。扇形里正中那张本来就整张立着，再拿一次是多余的，所以去掉了「拿起、放回」，只留「翻开」。
- 立起来的那张为什么是放大的、不是凑近的：它和扇面在同一个远近上，往上走的时候还夹在左右两张中间，看着像从扇子里抽出来的；要是往镜头凑，一动就盖住右边几张的标题。
- 立起来的那张离开以后，两边的牌往中间合拢：不合拢会露出前一张牌的半截正文，乱。
- 转得快只探头：每张都立起来再落回去，快翻的时候是一上一下的活塞，看不清。每秒转过一张半以内算「停下来看」，超过五张算「在翻」，中间渐变。
- 牌多的时候两头怎么办：离正中远到快出屏幕的，越挤越紧，挤成一沓边，看得出两头还有；挤到看不见的不画（三十八张的盒子同时只画十九张）。转到头，头一张、末一张停在屏幕边上不再往里走。
- 牌只有两三张：错开得大一点，每张露出大半张。四张到八九张：还是只露标题那一条，整把摆在正中（露半截正文反而乱）。
- 开着盒的时候镜头不晃：牌是按「镜头正对着」摆到屏幕上的，一晃整片会偏到一边。
- 现成的扇形、弧形轮播组件（Framer、21st.dev 上有十几个）都是网页框架里的，最多二十张、不管挤边，拿不来直接用；借的是它们的做法：排在弧上、碰到的那张抬起来压在上面、拖动带惯性、停在最近的一张上。

没做的和没验证的：

- 真机上没看过。转的时候跟不跟手、松手滑多远合不合适、立起来那一下的快慢，只能上手说；参数都在 `box.js` 最上面那张表里（`follow`、`fling`、`riseUp`、`riseDown`、`poke`、`slow`、`fast`、`sag`）。
- 立着的那张只是牌面，没有接正文：正文在主站是另一页朴素的阅读器，按「读、写保持又快又素」不放进三维里。从牌到正文怎么过去还没做，所以读过的牌点了没有反应。
- 一屏看不全。如果用下来发现常常要「全部标题一起看」，第一版那种叠着摊开可以作为另一个看法加回来（代码在 git 历史里，提交 deb7fb5）。
- 牌不能拖去别的盒子、不能排序、不能删；拆完的邮包也还装不进盒子（下一步）。
- 书、本子、邮包抽出来以后点一下还是放回去，只有牌盒是「点它打开」。等书和本子有了「里面」再统一。
- 盒盖只是往后掀，盒子里面是黑的；扇子的下沿压着盒口，看着像从盒里出来的，但牌并不真的插在盒里。
- 牌的标题、来处、「为什么存」都是编的；读过的状态不保存，刷新就回去。
- 横屏、电脑上能用但不是为它做的：屏幕矮，牌和立着的那张都小一号，弧也平。
- 灰盒没有这一步（灰盒没有档案架）。

请用户在手机上留意：

1. 抽出盒子再点一下打开，顺不顺；会不会想点却点成了放回去。
2. 这把扇子是不是你原来想的样子：弧够不够弯，牌的大小、露出来的那一条宽不宽。
3. 左右划：跟不跟手，松手以后滑得多了还是少了，一张一声对不对。
4. 正中那张自己立起来：喜欢，还是嫌它老在动；立着的那张够不够大。
5. 没读的在右头、背面朝上，点一下翻开：有没有「揭开」的感觉。
6. 一屏只看得清九条上下的标题，够不够用。

### 2026-11-14 三件家具（档案架、笔记本架第一版）

做了什么（都在书架那一页 `shelf.html`，一次只摆一件，颜色和零件是书的那一套）：

| | 是什么 | 怎么看出状态 | 抽出来 |
|---|---|---|---|
| 书架 | 书，书脊朝外 | 没读的腰封还在，在读的探出来垂丝带 | 封面，「打开读」 |
| 档案架 | 牌盒：布面的函盒，朝外一头装铜签框（纸签上写盒名）、一道盒盖的缝、一个铜拉环，上面压卷号。一个课题一盒，一类一个颜色。最后是没拆的邮包（牛皮纸捆麻绳，和拆包页那一包一个样） | 盒子越厚牌越多；有没读的牌的盒子探出来一点、顶上露一枚签 | 盒子的大面：卷号、哪一类、盒名、几张、几张没读。邮包有一个「去拆这一包」，连到拆包页 |
| 笔记本架 | 本子：布脊纸面的硬皮本，深色布脊包到封面五分之一，封面贴纸签写本名和页数，右边一道松紧带。封面朝外放，往后仰着靠着 | 本子越厚页越多；今天写过的探出来、垂着丝带 | 封面，底下写哪种本子、多少页、几天前写过 |

怎么换：底下一排三个小记号（不写字，现在这一件亮着、底下一个点），点哪个去哪个；按在这一排上左右划也行；电脑上左右箭头。不做整屏左右滑，因为手指在架上左右划已经是「划过」。换的时候镜头顺着墙横着走：这一件走出屏幕，下一件从另一头走进来，约零点七秒。换走再换回来，书架上改过的读没读还在。抽出一件的时候记号和把手都收起来。

几个取舍：

- 三件用同一种架子（胡桃木、线脚一样），层高各不一样（书 29、牌盒 17.5、本子 25.5 厘米），宽和层数跟着东西的多少自己定。件数少的两件按「每层摆满」来定宽，不然像没摆满的书架。
- 牌盒立着、窄的一头朝外，厚度才看得见（主站纸模版也是盒厚等于件数）。
- 本子封面朝外，是照 11-04 的笔记本设计稿；也因为本子只有几本，书脊朝外的话一排细条认不出是本子。
- 牌盒和本子没有做「没读 / 读过」那样的两种颜色：颜色只说它是哪一类。

没做的和没验证的：

- 翻开本子写字没做，本子抽出来只能看、转、放回去。打开牌盒看牌同日做了（见上面「开牌盒」，现在是扇形）；拆完的牌装进盒子还没做。
- 真机上没看过。换家具那一下中间有一瞬间只看见墙（下一件在镜头外搭好），手机上顺不顺要用户看。
- 牌盒顶上那枚签、本子的松紧带都是最简单的样子；牌盒是直角的方盒子，没有做盒盖的厚度和切角。
- 牌盒上的卷号、邮包的数量、本子的名字都是编的；改的东西不保存。
- 灰盒外观没有做这两件（记号不出来）；进门页最下面一层摆的牌盒和本子还是原来的样子。
- 三件现在是一次摆一件、镜头横着换，不是同时摆在一面墙上。

请用户在手机上留意：

1. 三件各自一眼认不认得出是书、是牌盒、是本子。
2. 底下那排记号找不找得到、碍不碍眼；点和划哪个顺手；换的那一下顺不顺。
3. 档案架：不看字，能不能看出哪盒牌多、哪几盒有没读的；牌盒和邮包好不好看。
4. 笔记本架：封面朝外对不对；本子像不像本子。
5. 下一步先做哪个：打开牌盒看牌，还是翻开本子。

### 2026-11-14 书的颜色和款式

起因：用户在手机上看过书架页，说清楚和亮度够了，接着指出「书只有两个颜色，卡牌、笔记本可能也是两个颜色」，要求按高标准重新定颜色和款式，不要拘泥于现有的两种，「这两个样式也不好看」。

原来为什么是两个颜色：读没读是靠「整本换颜色」说的。没读的一律包牛皮纸（米色），读过的六种布面全是深色（明度都在二三十），款式只有一种（皮签加三道竹节）。所以整面墙就是米色和深色两种，分类的颜色几乎看不出来。

现在的做法（都在 `kit.js` 外观表 `study.bind`，一本书的装帧由 `bindOf` 从书名算出来，同一本书排在哪、读没读都是同一个样子）：

| | 原来 | 现在 |
|---|---|---|
| 颜色说的是什么 | 读没读 | 这本书是哪一类。一类一个色系：藏青、枣红、青绿、石青、赭黄、墨（第七个绛紫留给以后更多的分类），每个色系三个深浅 |
| 款式 | 一种 | 四种，按书名散开：上下各两道线、上下各一道宽带、一格异色的皮签加三道竹节、贴一张纸题签（墨字）。深布烫金，浅布（石青、赭黄）印墨 |
| 没读 | 整本包牛皮纸 | 书脚围一圈腰封（浅色的纸，印两道细线），每本一样高（五厘米），一排书的腰封齐成一条线 |
| 读过 | 露出深色布面 | 腰封摘了 |
| 在读 | 探出来，垂丝带 | 不变 |
| 抽出来的封面 | 一种（两道框） | 跟着款式：两道框、宽框、书名在一格皮签里、左上角一张竖的纸题签；没读的腰封围到封面和封底，上面印分类和页数 |
| 书脊上的字 | 书多宽字多大 | 最大二点七厘米，厚书的书名不再撑满 |

几个取舍：

- 为什么用腰封：读没读还得一眼看得出，又不能再占掉颜色。腰封是人人认得的「买来还没读」的样子，占书脊的四分之一，是浅色的纸，比哪一种布面都亮，只靠明暗就看得出；位置固定在书脚，和书脊上半的纸题签不会混。
- 为什么这六个颜色：用户红绿色弱，红绿这条轴靠不住，所以按「明度 × 蓝黄」排开：墨最深，藏青深而冷，枣红深而暖，青绿居中，石青浅而冷，赭黄浅而黄。试过栗色，和胡桃木的架子混在一起，去掉了。试过每类里掺几本别的颜色（紫、麻布色），色弱的看法下和藏青、赭黄分不开，去掉了，同一类里的变化只靠深浅和款式。
- 这盏灯很暖，蓝光只剩三成多，表里写的布色和屏上看到的差很远（表里的石青是一块很艳的天蓝，在灯下才是一块灰蓝）。所以布色是按「屏上要看到的颜色」反推的：量屏上的颜色，和目标比，按比例改表，反复三四轮。石青已经到了这盏灯下能显示的上限。

量过的（一百二十本，手机竖屏，两倍屏，软件渲染；色差是 CIE76，色盲的看法用 Machado 2009 的矩阵在屏上实际显示的颜色上算）：

| 色系 | 屏上的颜色 | 明度 L* | 腰封比它亮几倍 |
|---|---|---|---|
| 墨 | #312517 | 16 | 9.6 |
| 藏青 | #3B4050 | 27 | 6.6 |
| 枣红 | #90392C | 36 | 4.8 |
| 青绿 | #4B7760 | 47 | 3.3 |
| 赭黄 | #C18535 | 60 | 2.0 |
| 石青 | #A2A897 | 68 | 1.6 |

色系两两之间最接近的一对：正常眼 25（藏青和墨），绿色盲的看法 22（青绿和石青），红色盲的看法 18（枣红和墨）。书脚那一段的亮度：没读的平均 .63，读过的平均 .18。整屏平均明度比原来低（四十本 .103 → .093，一百二十本 .146 → .110），因为大块的米色包书纸没有了。

没做的和没验证的：

- 真机上没看过。颜色在手机屏上的样子、腰封在最下面一层够不够显，要用户看。
- 整屏比原来暗一点（见上）。书名的对比没有降，但要是觉得又暗了，可以把灯再提一点。
- 石青的书配腰封，对比是六个色系里最低的（1.6 倍），靠腰封上沿的影子和两道线帮着分。
- 腰封是画在书脊上的一层纸，没有厚度；摘腰封没有动画，点「打开读」那一下是直接换的。
- 进门页跟着换了颜色和腰封（它和书架页共用书的画法），在读的记号还是顶上的白签；最下面一层的牌盒和本子还是原来的牛皮纸色和深色，等做档案架、笔记本架时用同一套颜色和零件。拆包页的牌背、牌面没动。
- 真书的分类不止六个、也不一定有分类，颜色跟着什么走（用户分的类、书自己的封面色）等接真实书目时定。
- 书脊上的字用的是手机系统的宋体，没有宋体的手机上是黑体。
- `docs/lab-study.jpg`、`docs/lab-shelf-clear.jpg`、`docs/lab-shelf-frames.jpg`、`docs/lab-door-frames.jpg` 里的书还是原来两个颜色的样子，这一轮的前后对比在 `docs/lab-books.jpg`。

## 拆包（`index.html` + `pack.js`）

一包没拆的剪报从上面送到眼前，沿封口横着划开，五张牌背朝上落到桌上，一张张点开，翻开的再点一下拿到眼前看，最后向上划或点「收下」，下一包送到。右上角是声音开关和「外观」。这一页只做了旧书房和灰盒两种外观（写在 `index.html` 的 `<html data-looks>` 上）。

开法：2026-11-12 用户在手机上试过，定「热闹」（顿帧、闪光、火星、镜头一震）。「安静」那一套参数还留在 `pack.js` 开头的 `MODES` 表里备查，地址加 `?mode=quiet` 才进；系统开了「减少动态效果」的设备默认走安静。

还可以接着调的（用户没提就先不动）：划开跟不跟手、一格一格的声音和震动；发牌的快慢、「全部翻开」够不够；牌底光晕（越亮这篇越长）；拆到第三包、第五包还想不想拆。

## 一眼看全（`shelf.html` + `shelf.js`）

一座立体的书架，多少本书都整座装进一屏（本数多了架子自己加宽加层）。读没读只靠物件的样子说，不靠色相、不贴标签：没读的书脚围着腰封（一圈浅色的纸，灰盒里是整本包白纸），读过的摘了，在读的探出来一截、脚下垂一条丝带（或者顶上露一枚签，工具纸里换）。

2026-11-14 起屏幕上只有架子和底下一排换家具的记号（见上面「三件家具」）：排法、在读的记号、本数、声音、外观、去拆包和进门的链接都在底下的工具纸里，点最底下那道小把手（或者按住往上划）才出来。不带参数打开是四十本（用户自己的书是三十八本）。

1. 上架：书一本本从外面推进去，镜头同时往后退到看全；点一下屏幕快进。
2. 划过：手指按在书脊上划，碰到哪本哪本探头，一本一声一震（越厚的书声音越低），手指上方的小签报书名。电脑上鼠标移过去就探头。
3. 抽出：松手，那本滑出来、转过封面飞到眼前；左右拖动转着看；底下是「打开读」和一条读到哪的细线，读没读跟着进度自己变（2026-11-14 前是「没读 / 在读 / 读过」三个按钮手标）。
4. 放回：点「放回去」或点空白处，飞回去、推进去一声闷响。
5. 换排法（工具纸里）：「按类放 / 按读没读放」，整面书一起飞到新位置；按读没读放时，层板边上有小签写每组多少本，改过状态的书放回去会站到新的一组。
6. 换本数（工具纸里）：40 / 120 / 300，看到多少本开始觉得看不全。

2026-11-12 用户上手后答「过」。当时请用户留意的几件事（留作记录）：

1. 进来那一眼，不看底下那行字，能不能说出读过大概几成。浅和深的差别够不够。
2. 40、120、300 本，到多少本开始觉得太密、看不全。
3. 手指划过书脊，探头跟不跟手，一本一声对不对，小签挡不挡视线。
4. 松手就抽出，会不会老是误抽；抽出和放回的快慢。
5. 两种排法哪种是平时想看的；换排法那一下是痛快还是乱。
6. 改了读没读以后书架跟着变（变深、探出来、挪位置），有没有「这面墙是我读出来的」的感觉。

手感的强弱都在 `shelf.js` 开头的 `P` 一张表里（上架多久、探出多少、抽出与放回的时长、换排法绕多远、镜头晃多少）。书名和作者是编的，没有接真实书目，改的状态不保存，刷新就回到原样。

## 进门（`door.html` + `door.js`）

点开别人的链接，三秒看懂他在学什么，一个动作带走一排。人名、那句话、书名都是编的。

进法：2026-11-12 用户在手机上两种都试过，定「直接到」，不要敲门那一段。「敲门进」（一扇门、门牌、敲两下、门开、镜头穿过门，约 2.4 秒）留在 `door.js` 里对照用，地址加 `?way=knock` 才走，页面上不再有切换。

1. 到：点开链接，书架直接在眼前；屏幕顶上是「谁的书房」和他自己写的一句话。约一秒就能动。
2. 看懂：一座书架，一排一个科目。层板边上的签一枚枚冒出来（科目、多少本、读过多少），那一排书跟着抖一下。读没读和书架样机同一套：腰封还在的没读、摘了的读过、探出来带签的在读。最下面一层是他的牌盒和本子，样机里只是摆着。
3. 看书名：手指按在书脊上左右划，碰到哪本哪本探头、报书名；只是看，不抽出来。
4. 带走一排：按住一排往下拉，这一排的一份（都带着腰封，到你手里都是没读的）跟着手指一本本从架上出来，一本一声一震；拉到底就带走，过了六成松手也带走，没到就弹回去。捆成一捆飞进底下的邮包，他的书还在架上。层板上那枚签点一下，也是带走这一排。
5. 邮包：点开看带走了什么，可以倒回去重来。底下「再进一次」可以反复看到的那一下。

上手时请留意的几件事：

1. 从点开到看懂他在学什么，够不够快。顶上那句话加四排的签，是不是就够了，还缺什么。
2. 进法：已定「直接到」（2026-11-12）。
3. 往下拉带走：跟不跟手，一本一声对不对，六成这个线松手带走是太容易还是太难。
4. 往下拉和左右划会不会互相误触。
5. 拉着带走和点签带走，你实际会用哪个。
6. 带走的是一份都带着腰封的、他的书还在架上，这个意思看不看得出来。

节拍和强弱都在 `door.js` 开头的 `P` 一张表里（签什么时候开始冒、一枚隔多久，往下拉多少算到底，过几成松手带走，收拢和飞多久；敲门进的四行只有 `?way=knock` 用）。样机里没有接真实的分享链接，牌盒和本子不能带走，带走的东西不保存。

## 技术

three.js 0.186（`vendor/three/`，自带）只画物件，字用网页排；外观表里的花纹（纸浆、布纹、木纹、护墙板）是页面打开时用画布现场画的小图；旧书房另有三张扫描的材质图在 `vendor/tex/`（木头两张、书布一张，转换脚本 `tools/tex/to_webp.py`）；声音是 WebAudio 现场合成的，没有音频文件；苹果手机没有震动。书架上的书是一个 InstancedMesh（三百本也只画两三次），书脊的字画在一张图集上；抽出来的那一本换成单独的模型；进门页里带走的那一份是同一批书的第二个 InstancedMesh，用一张全是白纸包的图集。地址加 `?dev` 显示帧率和状态（进门页还显示从点开到能动用了几秒），书架页加 `?n=300` 直接进三百本，进门页加 `?way=knock` 走留作对照的敲门进。
