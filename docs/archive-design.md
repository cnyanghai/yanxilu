# 档案架、档案盒与打开后的页面 · 设计研究

2026-11-06 第一稿：只研究问题，不定方案。现状截图在本机 tools/out/ar-*.png、archive-current.jpg；参考墙 refwall-archive.jpg（维基共享，只在本机看）。

## 一、它现在是什么

三件东西，三层数据：

| 层 | 现在的样子 | 数据 |
|---|---|---|
| 档案架 | 一只黑漆重柜，六个格子按领域分（五个方向加「收件匣」），格里立着盒子；格下一条黄铜标牌写领域与件数；柜顶横匾「研究档案」 | 领域 = `domains` 加内置五个 |
| 档案盒 | 竖立的牛皮纸文件盒：盒顶露出色签（件的类型）、盒面是竖排题签（卷号加盒名）、底部件数、拉手孔；状态用小标（年更、在做红丝带、结卷朱印）；盒子宽度随件数变厚 | 课题 = 内置 `LIB.topics` 加自立 `aboxes`；字段 title / question / answer / origin / books / line / note / status / since |
| 打开后 | 整屏盖一张深色木桌：标题区（卷号、盒名、领域、立卷、状态、件数）→ 课题问题与"现在的答案"→ 一排牌（牌背：圆光夜读小景、题签、类型钱币、来源、宝石）→ 宝石图例 → 牌册（目录表，可折）→ 来龙去脉（从哪来 / 用到的书 / 用得上）→ 备考 → 操作 | 件 = `LIB.reports`（href 到专题页）加剪报 `clips`（正文在 Baba） |

另有「剪报夹」：领域格里一只牛皮纸档案袋，没拆的封着，点开拆封，牌飞出来；拖牌到盒上就装盒。

已经立得住的：一个问题一盒、盒里按件编号、盒随件数变厚、牌背与宝石表示读没读、拆封动效、桌面的"场"感。这些是产品逻辑，不动。

## 二、设计问题（按分量排）

### 1. 空格子比盒子多，架子像没进货
六个格子里四个只有虚线的"新档案盒"。真档案架的饱满来自密度：卡片目录柜是几十个一样的小抽屉，档案库是一排排同规格的盒子（参考 3、4、13 到 16）。空格子的虚线占位是"后台"的语言。

### 2. 架子和书墙不是一套家具
书墙现在是（或将是）胡桃木拱形书柜；档案架是黑漆重柜加黄铜牌，像从别的屋子搬来的。审视稿第一条"一个房间四种材质"在这里最明显。

### 3. 盒子的信息层级反了
盒面上最大的字是竖排盒名，但真正要一眼看到的是"这一盒有多少、读到哪、要不要年更"。现在件数在最底一行小字，状态是三种小标各自为政。卡片目录柜的抽屉只有一个黄铜标牌框加手写标签（参考 3），信息只有一条，反而清楚。

### 4. 打开后的页面是三种语言拼的
标题区和课题问题是"文档"，一排牌是"游戏"，牌册和来龙去脉是"表格"。三段之间没有过渡，桌面的木纹只是背景，牌没有真正"摆在桌上"（没有投影、没有散落感、没有翻过的牌和没翻的牌的区别）。手机上这一页要滚五屏。

### 5. 牌的身份不够
牌背全是同一幅夜读小景，只有题签和颜色不同；类型（档案 / 数据 / 计划 / 纪要 / 剪报）只靠一个钱币上的单字。真卡牌一副牌里每张的牌面都不同，牌背才一样；我们正好反过来，玩家看到的永远是牌背。

### 6. 件打开后跳出了书房
专题页（档案、数据、计划）是独立 HTML 在新标签页打开，剪报在阅读器里打开；一个在房间里、一个跳出去。

### 7. 收件匣与剪报夹两个"待归位"
格里的"收件匣"和领域格里的"剪报夹"都是"还没装盒的东西"，分在两处，规则要读四条说明才明白。

### 8. 手机
手机上档案架是六个格子竖排、每格一屏高，大部分是空白；桌面页五屏长。

### 9. 色弱
件的类型色签（蓝、绿、红、黄、紫）里红绿并列；宝石"青读了 / 金批注 / 朱结卷"靠颜色。类型和状态都要有形状或文字兜底。

## 三、参考里能借什么

| 参考 | 借什么 |
|---|---|
| 卡片目录柜（参考 1 到 4） | 密度与统一：同规格小格阵列，每格一枚黄铜标牌框加一张手写卡，一个拉手。和书柜同一种木头就是同一套家具 |
| 鸽笼格 / 国家档案馆取件格（5 到 7） | "待取"的表达：空格是正常状态，有东西的格子露出纸边。收件匣可以就是几个鸽笼格 |
| 文书匣 / 便携书桌（8 到 10） | 盒子打开是一个"桌面"：盖子翻开、里面分格、文具与纸各有位置。打开一盒的页面可以就是这只匣子翻开 |
| 档案盒与霍林格盒（13 到 18） | 盒子的真实形制：灰板、金属包边、前脸一张标签、绳扣。我们的盒可以更像这个，少一点"文件盒"味 |
| 字盘（22、23） | 一盒里很多件时的排法：浅格阵列，每格一件 |
| 瓷器柜（26、27） | 展示型的柜：有背板、有层、东西朝前摆。和"牌摆在桌上"的另一种想法：牌立在柜里 |
| Are.na 的 channel 与 block | 一件可以同时属于多个盒（block 连到多个 channel）；我们现在一件只在一盒。要不要允许"一件两盒"是产品问题 |
| Zotero 用户的抱怨 | 元数据不说明"为什么归这里"。我们的"课题问题 + 现在的答案"正是解这个的，是长处，要放到最显眼的位置 |

## 四、方向（请用户选，下一步出样稿）

A. **同一套木器**：档案架改成和拱形书柜同一种胡桃木、同一盏灯的卡片目录柜式矮柜（按专业流程在 Blender 里建，和书柜共用材质与光）；格子变成小抽屉阵列，一盒一抽屉，抽屉前脸是黄铜标牌框加一张卡（卷号、盒名、件数、状态一行写完）；空抽屉也是抽屉，不再有虚线占位。收件匣是柜顶上的几个鸽笼格。
B. **盒子即匣子**：打开一盒不再是整屏深色木桌，而是这只文书匣在桌上翻开：盖子内侧写课题问题与答案（像匣盖内贴的字条），匣内分格摆牌（每格一件，牌面朝上），匣外一张"来龙去脉"的索引卡。牌册与操作收进匣子边上的小抽屉。
C. **牌面翻过来**：牌默认牌面朝上（标题、一句话、类型图标、来源、读到哪），牌背只在"没拆封"时出现。类型用五种边框或角标形状区分，不靠颜色。
D. **件不出房间**：专题页在房间里的阅读器打开（iframe 或同页加载），和剪报一样有划线与批注。
E. **手机**：档案架改成一列抽屉（每行一盒），点开一盒是匣子的单栏版。

我的建议：先定 A 和 C（看得见的两件），B 随 A 一起出样稿，D 和 E 是实现问题由我定。顺序：出 A、B 的概念图（gpt-image-2，先报提示词与价钱）→ 用户选 → Blender 按专业流程建 → 出图进网页。
