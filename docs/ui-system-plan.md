## 二、它是一个什么样的"游戏"：一间书房

现在的导航是三个标签页（书墙 / 档案架 / 笔记本架）加顶栏。类游戏的网站不靠标签页，靠**场景里的物件**：

- **主场景**是一间书房：正面一堵书墙（拱形书柜），左边档案抽屉柜，右边笔记本架，前面一张书桌（展台、随手本、笔和墨），窗或灯给光。点哪件进哪件，进去是"拿到眼前看"（翻开的书、拉开的抽屉）。退出是放回去。
- **顶栏变成 HUD**：一盏油灯（布置）、放大镜（搜索）、羽毛笔（记一笔）、一枚印章（打卡），放在场景边上不进画。
- **手机**是同一间房竖着看：书墙、抽屉、架子变成上下三段可滑，或者一屏一件左右翻。切换条可以保留做"快速传送"，但样子要变成书签或路牌。

**屏幕模板只有七种**，全站所有页面归进去：

| 模板 | 样子 | 现在的哪些页 |
|---|---|---|
| 房间 | 书房全景，物件是入口 | 新增（首页） |
| 墙 | 一面柜子，格层里摆东西 | 书墙、档案抽屉（拉开）、笔记本架 |
| 翻开的书 | 对开两页，左目录右正文，书签标签 | 档案夹对开、笔记本翻开、书的目录与精读、图例与说明 |
| 卷轴 | 一张展开的纸，有封蜡 | 弹窗、确认、提示、剪报确认窗、技术卡 |
| 阅读 | 一整页平纸，顶部一条细木尺 | 阅读器（书与剪报）、专题页 |
| 牌 | 一张卡放大，正反面 | 卡的详情、书皮近看、自测卡 |
| 印册 | 一页印章格子 | 学习打卡日历、进度、周回顾 |

## 三、零件体系（设计系统）

从下往上七层，下层做一次上层到处用：

| 层 | 内容 | 谁做 | 数量 |
|---|---|---|---|
| 令牌 | 五色加明暗各三档、字号阶、间距阶、投影三档、圆角 | CSS 变量（`src/page.html`） | 一份 |
| 材质瓷砖 | 旧纸、米纸、牛皮、栗红皮、墨绿木、胡桃木、黄铜、蜡、软木，可平铺 | 生图 → 本地裁成无缝瓷砖 | 9 |
| 框 | 纸面板、木框、皮面、黄铜包边、书签签，九宫格 | SVG 形状填瓷砖，角花生图 | 5 |
| 控件 | 按钮三态（木牌 / 黄铜钉）、标签签、输入框（纸条）、开关（搭扣）、滚动条（丝带）、进度（蜡烛或墨水）、提示（小卷轴） | SVG + CSS，用框与瓷砖 | 约 10 |
| 图标 | 单线描徽章风，深褐线，约 40 个（领域、类型、状态、动作） | 生图出一张图标表 → 本地描成 SVG，或直接 SVG 手绘 | 40 |
| 字 | 标题（有衬线、带手刻感）、正文（高可读衬线）、手写（批注）；全部自带，不用 Google Fonts | 选现有开源字体（霞鹜文楷 / 思源宋 / 一款手写） | 3 |
| 英雄物件 | 书柜、书托、展台、摆件十种、抽屉柜、夹子三种、对开本、卡袋、笔记本两种、书桌、油灯、印章、羽毛笔 | 样式图（概念表）→ 生图 → 抠底 | 约 30 |
| 动效词汇 | 翻页、拆封、抽出、放回、落下、盖章、点灯、翻牌，各一种节奏与缓动 | CSS / Web Animations | 8 |

**状态语言**（色弱）：没读 / 读了 / 批注 / 结卷用章的形状与文字，不用颜色区分；类型用图标；红绿不并列。

**正文可读性**：奇幻 UI 最常见的失败是正文印在花纹上。规定：阅读模板与翻开的书的正文区一律平纸、墨褐字、对比度 ≥ 7:1，装饰只在边角。

**文件落位**：`vendor/ui/tiles/`（瓷砖）、`vendor/ui/frames/`（角花与框件）、`vendor/ui/icons/`（SVG）、`vendor/ui/props/`（英雄物件 WebP，桌面与手机两档）、`vendor/ui/kit.json`（每件的尺寸、九宫格切线、来源提示词的编号）。

## 四、生产线（不用 Blender）

```
样式图（概念表：主视图 + 细节 + 小样，带尺寸，HTML/SVG 灰盒或线稿）
  → 参考包（用户挑的图里对应的裁切，每次调用都带同一组）
  → 报提示词与张数 → gpt-image-2 带参考生成（单色底；小件合成零件表一张多件）
  → 本地：抠底（色键 / rembg）→ 修边 → 切九宫格或裁瓷砖 → 统一调色（comp_grade）→ WebP 两档
  → 入库 vendor/ui/，登记 kit.json
  → 并排过门（混进参考认不认得出）
```

要补的工具：生图脚本加参考图输入（现有 `fal_image2.py` 只走文生图，先验一次 edit 接口）、抠底与修边脚本、九宫格切片与瓷砖无缝化脚本、零件表切分脚本、对照墙脚本（书柜那次的能用）。全放 `tools/ui/`。

一致性四条：每次同一组参考图；提示词固定开头段（画风、线、光、底色）；相近物件同一张零件表出；全部出图过同一道调色。

## 五、阶段与门

| 阶段 | 交付物 | 门 | 生图约 |
|---|---|---|---|
| 0 风格圣经 | 用户挑十到十五张（房间全景、书架、书皮、对开本、卡与纸、五金小件、图标、配色各一两张）；我写一页圣经（色板、线、光、物件语言、动效词汇）加三件试笔：一块纸面板、一只夹子、一组五个图标 | 三件试笔混进参考里认不出；用户过 | 6 |
| 1 原子 | 九张瓷砖、五种框、控件一套、字三款、图标二十 | 一页"零件墙"加一个用原子拼成的卷轴弹窗，桌面与手机 | 25 |
| 2 打样 | 档案夹三屏静态样稿（抽屉 → 夹子 → 对开），真零件拼 | 与魔法觉醒三屏并排；手机单栏 | 20 |
| 3 房间 | 书房主场景、HUD、场景式导航（保留切换条做传送） | 从房间进出三处不迷路；首屏图量 ≤ 1.5 MB | 15 |
| 4 铺开甲：书墙 | 书柜场景按绘本重出（现有 Blender 构图当底稿）、书皮体系收敛（装帧库从五种收成一种厚涂系，老书皮重画或退役）、书托与展台、摆件十种 | 整面墙与参考并排；书名可读 | 60 |

| 6 动效 | 八个动效词汇落到真页面；可选翻页声 | 每个动作 ≤ 400 毫秒、可关 | 0 |

## 六、预算与节奏

生图约 155 张，重滚按一半算约 230 张，gpt-image-2 中档约 0.38 元一张，**全套约 90 元**。阶段 0 到 2 约 20 元就能看到完整的档案夹三屏，到时再决定铺不铺开。

## 七、风险

- **返工面**：书柜场景、老书皮、五种装帧库都要收进一种画风，阶段 4 最重。先用档案夹打样验证画风能落地再动书墙。
- **一致性**：生图每次是新手，靠参考包、固定提示词、同表出图、统一调色四条压住，剩下本地修。
- **性能**：每屏图量设上限，瓷砖与框复用，英雄物件两档尺寸懒加载，WebP。
- **可读性**：正文区平纸高对比，写进圣经。
- **版权**：参考只在本机看；生成物自有；不用任何游戏的资产或角色。
- **两版共用**：公开版与服务器版同一套零件，剪报等服务器专有功能只多页面不多零件。
