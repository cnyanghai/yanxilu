# 研习录奇幻界面体系 · 蓝图与生产计划

2026-11-06 立，同日晚按用户口述的设想改写为蓝图。用户定：**画风绘本厚涂；主题先只做墓地一套，三个区共用；首页是一进 App 的独立一页，一片墓场，上面放选项；进场戏全长 3.5 秒、短版 0.8 秒；骷髅要**。目标仍是一个完整、成体系、像游戏的网站和 App（同一套网页，App 即 PWA）。风格细则在 `ui-style-bible.md`，进场戏分镜与灰盒原型在 `ui-scene-motion.md` 与 `ui-motion-proto.html`，样图怎么做的在 `ui-craft-and-pipeline.md`。各件物件的详稿另开（档案见 `archive-design.md`，书柜三维流程见 `bookcase-production.md`）。

## 一、从四张风格图留下来的、被替掉的

上午四张风格图定下的旧纸米、橄榄绿、栗红那套色板已被墓地色板替掉。留下来仍有效的三条：**书即界面**（翻开的书是主要屏幕模板）、**概念表格式**（每件英雄物件先出一张主视图加细节加小样的概念表，当生图的样式图）、**五金语言**（护角、铆钉、搭扣、蜡封，现在加上铁链、锁与灯笼）。Pinterest 十三张收藏的用处逐张记在 `ui-craft-and-pipeline.md` 第一节。

## 二、它是一个什么样的"游戏"：一片月夜墓场

### 首页：墓场（进场页）

一进 App 先到这里，像游戏的标题画面。一张全景：残月、枯树、铁栅门、贴地的雾，中景三座大碑并排，碑额刻着 **书架 / 档案柜 / 笔记本**，一条小路穿过去，路边一盏点着的灯笼写着「继续上次」（回到上回停的那本或那页）。点一座碑，镜头推过去，接那个区的进场戏。
贴边不进画的四件 HUD：灯笼（布置与设置）、放大镜（搜索）、羽毛笔（记一笔，快捷键 N 照旧）、印（打卡）。公开版与服务器版同一张首页，服务器专有的剪报入口是碑旁一只信箱。

### 三个场

| 场 | 家具 | 内容由数据长出 | 进场戏（`ui-scene-motion.md`） | 点进去 |
|---|---|---|---|---|
| 书架 | 墓碑书架：拱顶碑形，碑额刻领域名，三层格，土堆底座；每个领域一座，横向排成一列 | 书脊与封面照旧由数据生成，未读的是幽灵、在读的旁边点灯笼、读完的刻进碑 | 地抖、碑架颤抖升起、幽灵汇聚凝成书 | 书抽出放大到石祭坛上翻开（展台 → 目录 → 阅读器） |
| 档案柜 | 一座座小碑，碑面是档案夹封面，刻着夹名与篇数 | 碑数等于夹数，碑上的计数等于卡数 | 地抖、小碑错开长出、文章化卡飞入 | 碑面翻开成活页对开（左页卡袋、右页选中卡；`archive-design.md` 第六节） |
| 笔记本 | 空地，一排骷髅书童各捧一本 | 骷髅数等于本子数，随手本的那个最前 | 一只手先伸出、骷髅错开爬出站定、闲时呼吸 | 骷髅把本子递到前面，翻开成对开（现有随手本的两页） |

退出一律是"放回去"：书回格、碑面合上、本子递回。切换条退役，三个区之间靠首页或 HUD 的灯笼菜单传送。

### 手机

同一片墓场竖着看：首页是竖构图的另一张背景，三座碑上下排；各场一屏一座碑或一排骷髅左右滑；进场戏同一套只是家具更窄；粒子上限减半。

### 屏幕模板七种

| 模板 | 样子 | 哪些页 |
|---|---|---|
| 墓场 | 全景，碑是入口 | 首页 |
| 碑列 | 一排家具站在地上，雾在脚下 | 书架、档案柜、笔记本三个场 |
| 翻开的书 | 对开两页，左目录右正文，书签标签 | 展台与目录、档案夹对开、本子对开、图例与说明 |
| 卷轴 | 一张展开的旧纸，有蜡封 | 弹窗、确认、提示、技术卡 |
| 阅读 | 一整页骨白平纸，顶部一条细石尺 | 阅读器（书与剪报）、专题页 |
| 牌 | 一张卡放大，正反面 | 卡的详情、书皮近看、自测卡 |
| 印册 | 一页印章格子刻在石板上 | 学习打卡日历、进度、周回顾 |

## 四、生产线

四条路，各管一类东西，最后都进同一道调色与同一面对照墙：

```
背景与零件：样式图（概念表） → 报提示词与张数 → gpt-image-2（fal_image2.py，中档）
            → 抠底 cut.py → 切 nine.py / tile.py → 统一调色 → WebP 两档 → vendor/ui/ 登记 kit.json
英雄家具：  量尺（蓝本是乙试笔图） → Blender 粗模 → 高模 → 分层材质 → 看光（月光加灯笼） → 渲透明底
            → 必要时叠一道厚涂处理（笔触与纸纹）让它和生图的零件像一家 → WebP
角色：      丙试笔图当角色表 → Blender 建模（圆润低模）→ Rigify 绑骨 → 四套动作 → 渲序列帧（每套 12 到 24 帧）
            → 雪碧图 → canvas 按帧播放
由数据长出的：书脊封面、卡的字、本子纸面、计数、状态印 → 代码，叠在上面三层之上
```

一致性四条：提示词固定前导段；同类物件同一张表出；全部出图过同一道调色；三维渲染的光与生图的光方向一致（月光从上、灯笼在近处）。每件东西的小循环：样式图 → 生成或建模 → 抠底切片 → 进页 → 并排参考过门，门不过不往下走。

## 六、预算与节奏

生图约 75 张，重滚按一半算约 110 张，中档 0.376 元一张，英雄件过门后高档重出约 10 张，**全套约 55 元**。阶段 0 约 2.3 元，阶段 0 到 2 约 16 元就能看到首页与书架场的完整样子，到时再决定铺不铺开。三维与角色不花钱花时间：书架模块约一天，骷髅四套动作约两到三天。

## 七、风险

- **恐怖感**：日用的学习工具，墓地主题一不小心就阴森。圣经定了"温和不恐怖"，试笔丙专门验骷髅的脸。
- **进场戏疲劳**：长短版、点一下跳过、减少动态时不演，三条写进代码不写进"以后"。
- **首页多一跳**：原来打开就是书墙，现在多一页。灯笼「继续上次」一键回到上回的地方，手机上首页可下滑直接进上次的场。
- **骷髅工作量**：角色是整套里唯一要绑骨的东西，放在阶段 3 单独做，前两阶段不等它。
- **一致性**：生图、三维、代码三种来路要像一家，靠同一道调色、同一方向的光、同一面对照墙。
- **性能**：粒子上限 60（手机 30）、背景 WebP、家具两档尺寸懒加载、canvas 只在进场时开。
- **可读性**：暗底上的字加描边，正文区平纸，写进圣经。
- **版权**：参考只在本机看；生成物自有；不用任何游戏的资产或角色。
