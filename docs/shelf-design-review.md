# 书架的设计审视（2026-11-04）

以网站设计师的眼光看书架三件家具（书墙、档案架、笔记本架）加展台与桌面。依据是 2026-11-04 晚的线上版本截图（本地 tools/out/rv-*.png，不入库）。先说立得住的，再说问题，最后给做的顺序。每条尽量写成能检查的话，不写"更高级一点"这种。

## 一、已经立得住的

- 一套暖纸色的底子：纸白、墨黑、朱砂、黄铜，三件家具和阅读器都在这套色里，没有跑偏。
- "数据长成家具"这个想法没有现成产品有：书脊厚薄是读的时间、抽出半截是在读、盒子变厚是资料变多。这是研习录最值钱的地方，审美的提升都应该服务它，不能为了好看把它盖住。
- 老书皮装帧那一排，远看已经有真书的密度和杂色；蜡烛、沙漏、绿萝这些小物让墙活了。
- 桌面（打开一盒）的美术方向是对的：深木、圆光牌背、黄铜数字，有一个明确的"场"。

## 二、问题（按严重程度）

### 1. 一个房间，四种材质语言

书墙是浅米格纹墙加薄木条，档案架是黑漆重柜加黄铜牌，笔记本架是一块平涂的深棕板，桌面是深色实木。四件东西像从四家店买来的，光也各打各的：老书皮按左上一盏灯画了，墙面和书架板却没有影子，档案架是均匀照明，笔记本架完全没有光。

要做到：一个光源（左上，和老书皮一致）、一种木头（定一种色与纹，书架板、柜子、笔记本架、展台都用它）、一种阴影柔度（同样的模糊半径和透明度）。这一条做好，其他家具不用重画就会"住进同一个房间"。

### 2. 贴图感的根子在墙面和书架板，不在书

- 墙面是一张细格纹平铺，读起来像方格纸不像灰泥或亚麻，而且没有大尺度的明暗变化，一眼看出是重复贴图。
- 书架板是一条没有厚度的薄带：没有前沿、没有托架、板下没有影，书和板之间没有接触阴影，书脊在墙上也没有投影。于是书是"贴"在墙上的，不是"立"在板上的。

要做到：墙面两层纹理（大尺度的光照渐变加小尺度的灰泥颗粒，颗粒用现成的 `--grain` 那套运行时噪声即可）；板有 10 到 14 像素的前沿厚度和板下 6 到 10 像素的暗影；书底部 3 像素的接触阴影；书在墙上的软投影随光源方向偏右下。老书皮第二轮已经证明这些用 CSS 混合模式就够，不必换图。

### 3. 版面：墙上一半是空的，页头却占了两行

- 四层书架的间距是固定的，每层书高约 230 像素而层距约 400，三分之一的墙是空白；读完的书、十册函套都不能把这块空补上。
- 页头：大字"书架"、三段切换、加一本书、四个筛选、布置，两行控件压在房间上面。桌面上占 130 像素，手机上把书墙推到第二屏（390 宽的截图里书墙从 730 像素才开始，首屏只看到控件）。
- 底部的图例（立着、抽出、盖章……）是说明书，不是房间的一部分。

2026-11-04 用户同意。要做到：层距等于本层最高的书加 36 像素；页头收成一行（标题去掉，和主导航重复；筛选收进"布置"或做成书架右上角的一枚小标签）；手机首屏必须看到第一层书；图例改成"怎么看这面墙"的一个问号弹层。

### 4. 书太整齐，像样品架不像书房

全部等高、全部笔直。2026-11-04 用户同意，但问：读完的书多了不能都横放。规则定为：平放只表示"这一格最近读完的"，每格至多一摞、至多三本，再早读完的仍竖放盖阅印；一摞超过三本就把最早的一本立回去。真书架的生动来自三样可控的"乱"：每格末尾一本微斜靠着（约 8 度）、读完的书平放成一小摞、高矮参差。这些都可以是有意义的：平放一摞是"读完"，比盖章更一眼；斜靠的是这一格最近碰过的一本。规则要少，一格最多一处"乱"，否则读不出书名。

### 5. 老书皮的书脊是封面切下的一条

远看成立，近看没有书脊该有的结构：没有竹节（raised bands）、没有题签框、没有顶脚的烫线。书脊是书墙上看得最多的面，值得单独做一套"脊模板"叠在切条之上：五道竹节的高光与阴影、中段一块题签、上下两道金线。或者按 REFERENCES 里的路子另找带书脊的公版扫描。

### 6. 展台是一张白卡，房间里唯一的"界面"

书墙旁边的展台是圆角白卡、阴影、按钮，是后台管理系统的语言。它应该是房间里的一件东西：一个斜面书托或读书架，木头和书架同一种，书立在上面，进度条已经做成书口的样子很好，其余的按钮可以留着但收进木头的边框里。桌面已经做到了"进入一个场"，展台没有。

### 7. 档案架的空格比盒子多

六个格子里四个只有虚线的"+ 新档案盒"，像没进货的货架。两个办法：格子数跟盒子数走（盒子加一，格子长一）；或者空格子画成浅的、退后的背板，占位符只在指上去时出现。另外黑漆柜和浅橡木书架不是一套，见第 1 条。

### 8. 笔记本架是最弱的一件

一块平涂的板，没有透视、没有光，本子没有影子。它应该和书架板同一块木头，有斜面（样稿里有，上线时没做）、本子微仰、架下有影。本子封面的布纹和黄铜题签已经够了，缺的是把它放进房间。

### 9. 字体

标题用思源宋体没问题；界面用 Barlow 这种工业无衬线，数字用 Barlow Condensed，和书房的气质有冲突，尤其在书架标牌、笔记本页脚这些"房间里"的文字上。建议房间里的小字换成人文无衬线或楷体（霞鹜文楷是 OFL 授权，可以自带进 vendor/fonts，正好给笔记本一种手写感），仪表盘和线网图保留 Barlow。

### 10. 动效：有点睛的，缺连贯的

已有的烛火、沙漏、指到书抬起、拆封都好。缺的是"镜头"的连贯：打开一盒是整屏切成深色，像换了一个应用；点书飞到展台已经有了，但书架载入是一次性出现的。建议：载入时四层书架自上而下错开 40 毫秒落定；打开一盒从盒子的位置放大过渡到桌面（View Transition 已经在用，给盒子和桌面同一个 view-transition-name 就行）；笔记本翻页做一次 CSS 三维翻页。所有动效 200 到 320 毫秒，缓出，不弹。

### 11. 颜色与色弱

主色没问题。领域的小色点（红、橙、绿、蓝灰、紫）成对出现时，红与绿要靠明度差分开，不能只靠色相；现在红点和绿点明度接近。所有用颜色表达的状态旁边都已有文字，这一点保持。

## 三、生产方式

按项目的规矩，插画级的东西不用代码硬画。这次要的东西大多不是插画，是材质与光：

- 墙面灰泥、橡木板、亚麻：Poly Haven 和 ambientCG 有 CC0 的实拍材质，取 512 像素的一张做底，用 CSS 混合叠光，和老书皮同一条路。
- 阴影、厚度、接触阴影：纯 CSS。
- 书脊模板、斜靠的书、平放的一摞：CSS 变换加现有画布，不需要新美术。
- 字体：霞鹜文楷自带，一个 woff2 子集约 3 到 5 MB，要按用到的字做子集。

## 三之二、要不要用 Blender（2026-11-04 补）

用户问能不能用 Blender 生成书架、书皮、摆件。可以，而且三维版（yanxilu-world）已经在用 Blender 按尺寸表建家具，两边可以共用同一套模型。网页版的用法不是实时三维，是**预渲染**：Blender 里建好、打好光、渲成透明底的 WebP，网页里当图片摆。

分工按"变不变"来定：

| 东西 | 变不变 | 谁出 |
|---|---|---|
| 书架板、托架、档案柜、笔记本架、展台书托、十件摆件 | 不随数据变 | Blender 预渲染，一件一张透明底 WebP（20 到 60 KB） |
| 墙面、木纹、亚麻 | 不变 | CC0 实拍材质做底，CSS 叠光；或 Blender 烘焙一张 |
| 书脊、封面、盒、牌 | 每天随数据变（数量、厚度、书名、状态） | 仍由 CSS 画，但光照层可以由 Blender 出：渲一张书脊的 AO 加高光加竹节法线的透明叠层，代码只上颜色和书名 |
| 老书皮封面 | 不变 | 继续用公版扫描 |

代价三条：机位固定（正面一个角度，网页版本来就是正面）；时辰变光要么渲多套（晴窗、夜读、雨天，正好和三维版的三套一致），要么只在 CSS 里叠色调；每件资产要进 vendor 自带，国内可达没问题。

用户规矩（2026-11-04）：Blender 的设计一律在桌面版窗口里做，边做边截图看，用 yanxilu-world 的 tools/blender/mcp_call.py 驱动；无头渲染只出成品。本机 WSL 的 Blender 4.0.2 可用，但这个包没带降噪器，CPU 渲一张 1600 宽要 128 采样以上，几分钟一张，做静物够用。试渲脚本在 tools/blender/shelf_test.py。

试渲结果（docs/mock/blender-shelf.jpg，第四次才渲对，前三次分别栽在父子变换、无降噪器、立方体尺寸算半）：几何上的东西 Blender 一次到位，板的厚度与透视、托架、书底的接触阴影、斜靠的书、平放的一摞、板在墙上的影子，都是真的，CSS 要一样样手画。但材质没到位：布面是平涂的、墙面是白的、颜色被色调映射洗淡，这些要靠真正的材质贴图（CC0 实拍）和调光，不是几行节点能解决的，是另一轮工作。

结论：**静物与光照层走 Blender，数据驱动的东西走 CSS。** 具体到第一步「光与木」：板、托架、板下影用 Blender 渲成透明底 WebP 替换 CSS 的板；墙面用 CC0 灰泥贴图加 CSS 叠光；书仍是 CSS 加老书皮扫描，只从 Blender 借一张书脊光照层。

## 三之三、为什么二十二版还做不成蓝本，以及换路（2026-11-06）

原因，按分量排：
1. 目标是一张"像照片"的生成图，它的质感来自真实照片的统计（每块木板独一无二的纹理、磨损、灰尘、镜头和调色）；我们用四张平铺贴图加方块圆柱球去凑，是另一个生成过程，分区把平均明度凑齐也凑不出整体观感。
2. 几何：蓝本的线脚是真实的刨花型材和雕花，我们是积木；木纹是 1K 贴图盒投影，平铺重复、没有板与板的差别。
3. 光：蓝本是一盏物理一致的软光加遮蔽渐变；我们手调四盏灯加曝光，六七个自由度，每次改一组参数、十分钟看一次，二十二轮是在盲调。
4. 度量太粗：区域平均明度相等不等于纹理分布相等。

换路（蓝本本身就是答案，不该重画它）：
- 甲 直接切图：把蓝本（必要时先放大一倍）按拱顶 / 格层 / 底座 / 立柱九宫格切片，网页 CSS 拼装，书由代码摆。最省，前视图足够；缺点是格层只有一条、重复时光照渐变会重复（高通去掉低频光再叠 CSS 渐变可解）。
- 乙 投影贴图（用户提的"贴图贴在模上"）：相机对准蓝本机位，把蓝本投影烘焙到现有几何上。前视图等于蓝本，几何只负责分模块与微调；侧面和背面没信息，换机位会穿帮。网页版只看正面，可行；比甲多出的只有"几何上的分块坐标精确"。
- 丙 渲染引导重绘：用第二十二版的渲染做结构、蓝本做风格参考，图生图（gpt-image-2 edit 或 Nano Banana）出一张；几何是我们建的、每块搁板的像素位置已知，切片精确；画质来自模型。层数不同（3 到 6 层）各出一张，同参考同种子保持一致。每张约 0.4 到 1 元。
- 结论：先做丙，一张即见分晓；丙漂了就退回甲。Blender 的价值留给三维版和换机位，网页版不再用它逐像素追一张图。验收仍是混进参考认不出。

### 专业三维美术怎么从概念图做到成品（2026-11-06 补）

他们也先出图再建模渲染，能做到"一样"，靠的是六件事，我们一件都没按规矩做：
1. 读图不是抄图：概念图定设计与气氛，成品按物理规律重新做；物理正确的材质加光自然收敛到照片感，所以"看起来一样"。不追像素。
2. 建模分层：先粗模对比例，再高模。线脚是把真实型材截面沿路径扫出来的，雕花在 ZBrush 里雕或用现成扫描 / 套件（Megascans、Kitbash3D），不是球加环加圆柱。
3. 材质是"写"出来的，不是贴上去的：Substance Painter 里底材加边缘磨损、缝隙积灰、清漆层、每块板随机色相与纹理偏移，4K 起，贴图密度按每米像素数定。
4. 打光是看着调的：HDRI 给环境、两三盏区域光、实时预览里和参考并排或叠图翻看，一次只动一个量；用示波器和直方图比，不靠平均值。
5. 三成照片感在合成：分层渲染（漫反射、高光、AO、自发光）进 Nuke 或 PS 调色，加暗角、颗粒、镜头效果。
6. 时间：这样一件主要道具，中级美术两到五天（建模一天、UV 与材质一到两天、看光一天）。我们是三小时、脚本堆积木、十分钟一轮盲渲。

2026-11-06 用户定：以后都按专业流程做。书柜的阶段与门在 docs/bookcase-production.md。

对我们的含义：按这套走，脚本能做的有型材扫掠、每板随机、磨损与积灰遮罩、HDRI、分层与调色、EEVEE 实时并排；做不了的是雕花（用 AI 图生三维从蓝本局部出，或买现成）。预算两到三个工作段。否则走「三之三」的丙或甲。

## 四、做的顺序

| 序 | 做什么 | 为什么先做 | 大小 |
|---|---|---|---|
| 1 | 一个房间的光与木：统一光源、木色、阴影；墙面换两层纹理；书架板加厚度与板下影；书的接触阴影与墙上投影 | 解决贴图感的根子，三件家具同时受益，不动任何图 | 两天 |
| 2 | 页头瘦身与层距：页头一行、筛选收进下拉、层距跟书高、手机首屏见书 | 把房间从控件下面解放出来，手机尤其明显 | 一天 → 2026-11-05 已上线：层高 400 → 295，手机书墙顶部 730 → 189 |
| 3 | 展台与笔记本架进房间：展台做成木书托，笔记本架用同一块木头加斜面与影 | 消掉两处"界面感" | 一天半 |
| 4 | 书的生动：每格一处斜靠、读完平放一摞、老书皮脊模板 | 书墙的第二眼 | 两天 |
| 5 | 动效连贯：载入落定、开盒放大过渡、翻页 | 锦上添花，放最后 | 一天 |
| 6 | 字体：霞鹜文楷进房间里的小字 | 独立一项，随时可做 | 半天 |

验收还是那一条：截一张书墙，混进三张真书房照片里给人看，能被当成"效果图"而不是"网页截图"才算过。每一项做完都截图与上一版并排，不并排不算完。

### 技术决定（Claude 定）

- 2026-11-08 夜 盒子在代码里**不用 CSS 3D**（perspective + rotateY），改成正交投影的平面画法：正面是对齐像素的矩形，不经过任何变换；侧面是一条窄矩形（宽 = 盒厚 × .37，叠三成黑）；顶面是一片 4 像素高的平行四边形（叠两成白）；盒底两片模糊椭圆做接触影。原因：用户看线上说盒子发虚。放大三倍对照（docs/ui-archive-box-zoom.jpg）：三维变换的层被浏览器按整层重采样，字和线都软，盒面的颗粒重采样后成了一块块斑；参考 MYTHOS 的盒子竖边本来就是平行的（六之五量过，顶到底只偏 0.3°），正交画法反而更像。盒面不加颗粒、不加滤镜（滤镜会把面单独栅格化）。试笔稿 docs/paper-trial.html 还是 3D 写法，只当样稿看。

对我们是好消息：这是最适合 CSS 做的拟物。平色加两种阴影加一张颗粒就是全部，不需要位图；天然色弱友好（意义只靠明度与形状）。和墓园那条路正相反：那是「画里长界面」，这是「界面本身是材料」。

### 对三件家具意味着什么

- 整个书房变成一间纸板模型屋（纸模）：书架板是厚纸板条，书是硬纸书脊（赤陶、橄榄、米白、黑四色加字），档案盒是牌盒，笔记本是硬纸封面本。一种材料，三件家具自然是一套。第六节第 1 条「一个房间的光与木」改成「一个房间的纸与压痕」。
- 现有素墙色板（亚麻、橡木、黄铜）与纸模色板是近亲（同在暖棕一族），书墙现有的书脊与布面装帧能保留，木头换纸板、白卡换米白凹面即可。
- 要收掉的：地铁式彩色（五个领域的红橙绿蓝紫点、五种类型色）和纸模一族冲突。领域改用单字加卷号（周、地、金、货、司），类型改成一字签（数、档、剪、计、纪），状态仍用形状（丝带、圆签、方印）。线网图、足迹保留原样，不在本轮。

### 档案盒就是牌盒

- 盒：2:3 的立盒，像一包扑克牌那样**斜立**在层板上，一盒一包，一盒盒各有各的歪；赤陶与黑两色交替（按卷号奇偶），面上一个巨大的领域单字，细线双框，左上卷号。盒子的厚度就是牌数（越厚牌越多），不写数字。
- 打开：盒子立着、盖子翻开，牌从盒口抽出摊成扇。牌背黑卡铜字（领域单字加卷号，点线双框），没读的朝下、读过的朝上；牌面米白卡纸：类型一字签、标题、来源与日期与分钟、为什么存。
- 这和 11-04 审视里「牌背表示读没读」一致，也和用户「打开后直接卡牌」一致。开盒 A 案据此改成「盒口抽牌」；架子是层板（乙的架子、丙的一格一盒合并成「层板上斜立的盒」），甲案的抽屉和牌盒不搭。

### 结论

- **差距最大的一条是厚度。** 我们的盒薄得像一张卡贴了条边；参考是一块砖。盒厚按正面宽的三分之一起步，牌数只在上面加一点，「盒越厚牌越多」的意思还在，但不再是薄片。
- 第二条是**影子**。参考的盒子是「站在地上」的：盒底一圈暗、半影很大。我们的只有正面一道投影，所以像贴在板上。加地面接触影后，盒子立住了。
- 第三条是**盒面不该用纸片的规则**。切边亮线、顶边亮线是薄纸的特征；牌盒是哑光硬纸板，折痕处是干净的暗台阶。两套规则分开：薄的纸片（牌子、签、按钮、书脊）用 .slab，厚的盒体（牌盒、本子、书）用 .pack，盒面不加亮线。
- 转角、镜头高度、三面明暗本来就接近，微调即可。
- 摆放：参考是一盒直立、转 20°，牌靠在盒边。我们一排同向直立已经对了；开盒页的牌下一轮改成靠着盒斜立、底边露厚，和参考一致。

试改已经做进 docs/paper-trial.html（第三稿的盒子参数），两张拼图随之更新；三栏对照图（参考 / 改前 / 改后）只在本机 tools/out/paper/box-compare.jpg，含参考图不入库。本子与在读的书的厚度另算（本子 10px + 每页 1px，书 12px + 每页 1px），也都加了接触影。

## 六之八、新模型复审：材质与版面重画（2026-11-10）

用户换到新模型后说：重新处理这个项目，找提升的地方，必要就重做，不必迁就之前的建设。先把样张和三页现状整屏并排看了一遍，再决定做法。

### 复审结论：精修分段的顺序排反了

六之七的四类差距本身没量错，但按「调色 → 边与影 → 纹理 → 字与密度」一段段调，会一直对不上，原因有三：

1. **样张的识别度先来自版面，不是材质。** 样张整屏是一面拼起来的厚纸砖，牛皮纸底只当 8 像素的砖缝，奶油面占大半屏；我们是几片纸浮在一大片底上。精修 1 把底色照样张的「缝色」调深以后，深底露出四成，整页反而更褐、离样张更远。「底露太多」在六之七排在第四段，其实应该最先做。
2. **厚度的画法错了，不是数值错了。** 三阶暗条是硬线，画出来像描边；样张的砖是软边（左上亮、右下暗的内阴影）加一条同色的暗侧壁，再加近黑接触线和软影。
3. **纹理的工具到头了。** feTurbulence 只能出均匀噪点，出不了稀疏的深色小坑和几根纤维；而且每种颜色的纸各写一遍阴影和颗粒，三十多处写死的色值，改一处漏一处。

另外两条以前没写进规则的：

- **颜色要分工。** 样张里奶油是放内容的面，橄榄是数字砖，赤陶是品牌和主操作，一屏只有这四种纸。我们的顶栏、分段条、底栏、桌面都是同一种浅褐，没有分工。
- **选中不能靠红绿。** 赤陶和橄榄亮度几乎一样（97 对 95），对色弱用户是同一个颜色。所以选中靠明度（奶油砖对橄榄砖差 70 多级）加形状（压下去的坑、一道短条），不靠这两个色相。

### 没动的与还差的

### 材质之外的提升建议（都没动，等用户排序）

1. **页面瘦身。** 首页一个文件 1.3 MB。脚本 729 KB 里冻结的摆件库、墓园界面、独立 App 舞台、几套装帧约占 23%（约 165 KB），样式里冻结的场景与装帧约 57 KB；每个访客每次更新都要重新下载。建议把冻结的部分拆成按需加载的文件，墓园系列真要回来时再接上。
2. **样式表收口。** 三千行里按年代叠了四层设计，同一个选择器前后定义三四次，这次的黑砖、52 像素空档、按钮发暗都是旧规则压过新规则。建议下一步把书架三页用到的规则理成一份、旧的删掉，之后改样式才不会再踩。
3. **测试。** `abox_test.py`、`clip_test.py` 已过时；现在没有一条测试看得出「样式坏了」。建议加一条截图比对：三页两端各一张基准图，差异超过阈值就报。
4. **六之六留下的七条**（英语入口、书的生动、标志、数字字体、动效、笔记本第二版、暗色与多盒）顺序不变；其中标志这次顺手换了配色（奶油环加深色横条印在赤陶牌子上），形状没动。

### 过门与后续（2026-11-10）

用户看过前后图：**过门**。数字砖切换条、手机右下角的圆钮、三个架子的奶油框跟着这一版留下。

材质之外那四条建议里，前三条是技术上的事，由 Claude 排：

- **截图比对测试，已做。** `tools/tests/look_test.py`：书墙、档案架、开盒、笔记本架、足迹，手机与桌面各一张，加冻结的独立 App 两张，共十二张，对着 `tools/tests/look/` 里的基准比（基准缩到四分之一无损存，一共 476 KB）。日期钉死、动效全关、自己起一份干净的模拟服务，所以同一台机器上重拍逐格不变（连跑四遍都是 0 格）。判坏两条：变了的格子多于 24 格（每格 4×4 像素，差 5 级以上），或整页某个通道平均偏 1 级以上。自检过四种故意改动：奶油面亮 6 级、整页底色亮 3 级、按钮圆角 10 → 2、砖缝 8 → 10，都报了；独立 App 两张在这四种改动下都不动，说明它和主站的样式确实隔开了。样子有意改的时候加 `--update` 重拍，基准图跟代码一起提交。
- **页面瘦身，量过以后不做。** 上面写的 1.3 MB 是没压缩的大小；两个线上地址都开了压缩，实际传输是 372 KB。最大的一块（十件摆件的图，118 KB）压缩后只有 24 KB，把冻结的部分全拆出去最多省两成左右，而它们和主站代码在同一个闭包里互相引用，拆的风险比收益大。结论：不拆。真正每天让整页重新下载的是讲义和打卡快照（它们每天变、和代码打在同一个文件里），这一条记作待办，不急。
- **样式表收口，清点以后不做。** 上面第 2 条说「同一个选择器前后定义三四次」，说重了。逐条数过：2730 条规则里，同一个选择器（同一层 @media 里）写了不止一处的只有 49 个，写到三处的只有顶栏一个。其中 21 个是最后那段「一个房间」故意叠在基础样式上的外壳（顶栏、牌子、按钮、找一找、剪报条、放书卡、记一笔），另外 28 个散在线网、阅读器、独立 App 里。把两处合成一处并不保险：按钮这类元素会和别的类写在同一个标签上，挪动声明的先后会改掉谁盖谁，49 个里按最保守的判法只有 2 个能直接合。这一轮真正踩到的三个坑（选中的砖发黑、书墙上方 52 像素空档、回到档案架的按钮发暗）也都不是重复定义，是旧规则用另一个选择器管着新零件；这种只能改到哪清到哪，现在有截图比对兜着。结论：不做整表收口。

看得见的那一条先出了选项：黑色四选一 `docs/ui-cocoa-options.jpg`。现在的近黑 #2B2522（亮 38，几乎没有色相）、深可可 #3B2416（亮 41）、可可 #4D3020（亮 55）、和字同一个墨色 #3E1D00（亮 36）。全站的黑都走 `--pp-black` 一个变量，选哪个都只改这一处。Claude 的建议是深可可：有了暖色相、仍是全页最深的一档，和深牛皮纸书脊还差 28 级；可可浅一档以后和深牛皮纸书脊只差 14 级，一排书里分不开；墨色偏红，和赤陶书脊抢。等用户定。
