# SQL 第 1 课 · 数据库、表、行和列：装好 DB Browser，建第一张表

> 45 分钟 · SQL 第 1 / 36 课

> 还没装 DB Browser 的话，先花 10 分钟按 [准备日讲义](../../daily/2026-10-11.md) 第一节装好，建一个 `practice.db`。

## 本课目标

1. 说清楚数据库、表、行、列分别是什么。
2. 会用 `CREATE TABLE` 建表，知道 SQLite 常用的三种类型 `INTEGER`、`REAL`、`TEXT`，知道主键是干什么的。
3. 会用 `INSERT INTO` 插入数据，用 `SELECT ... FROM` 把表查出来。

## 讲解：一张报销台账就是一张表

设想你在核查一个虚构单位的《差旅报销台账》，要和《请假登记表》对照，看有没有人“请假那天却报了出差”。

| Excel 里 | 数据库里 | 说明 |
|---|---|---|
| 整个工作簿 | **数据库**（database，SQLite 里就是一个 `.db` 文件） | 装很多张表 |
| 一个工作表 | **表**（table） | 一类事物一张：报销一张，请假一张 |
| 一行 | **行**（row / record） | 一笔报销、一次请假 |
| 一列 + 列标题 | **列**（column / field） | 姓名、工号、金额、日期…… |

和 Excel 的关键区别：**每一列在建表时就定好类型**。

- `INTEGER`：整数（编号、天数）
- `REAL`：小数（金额）
- `TEXT`：文本（姓名、工号、日期。SQLite 的日期统一写成 `'2026-04-08'` 这样的文本，按这个格式排序、比较都不会乱）

**主键**（`PRIMARY KEY`）是每一行的“身份证”，不能重复。台账里的报销单号天然适合当主键：同一张单子不可能登两次——如果真登了两次，数据库会直接报错，这本身就是一道核查关口。

## 建表加数据脚本

打开 DB Browser → 打开 `practice.db` → **Execute SQL** → 粘贴整段 → `Ctrl + Enter` → 点 **Write Changes** 保存。

```sql
-- 第 1 课：差旅报销台账（数据全部虚构）
DROP TABLE IF EXISTS travel_claims;

CREATE TABLE travel_claims (
    claim_no   INTEGER PRIMARY KEY,   -- 报销单号，主键
    name       TEXT,                  -- 姓名
    emp_no     TEXT,                  -- 工号（虚构格式）
    dept       TEXT,                  -- 科室
    trip_date  TEXT,                  -- 出差日期
    city       TEXT,                  -- 出差地（虚构地名）
    amount     REAL                   -- 报销金额（元）
);

INSERT INTO travel_claims (claim_no, name, emp_no, dept, trip_date, city, amount) VALUES
    (2001, '甲一明', 'E-0101', '综合科', '2026-04-08', '云溪市', 1320.0),
    (2002, '乙二红', 'E-0102', '财务科', '2026-04-08', '云溪市', 980.5),
    (2003, '丙三华', 'E-0103', '项目科', '2026-04-10', '石桥县', 2150.0),
    (2004, '丁四强', 'E-0104', '项目科', '2026-04-15', '北岭市', 760.0),
    (2005, '戊五芳', 'E-0105', '综合科', '2026-04-15', '北岭市', 1890.0),
    (2006, '丙三华', 'E-0103', '项目科', '2026-04-22', '云溪市', 1405.0),
    (2007, '己六军', 'E-0106', '财务科', '2026-04-23', '石桥县', 640.0);
```

切到 **Browse Data**，选 `travel_claims`，能看到 7 行。

逐句看：

- `DROP TABLE IF EXISTS ...;`——有同名表先删掉，脚本可以反复跑，不会报“表已存在”。
- `CREATE TABLE 表名 ( 列名 类型, ... );`——列之间逗号隔开，**最后一列后面不加逗号**。`--` 后面是注释，不执行。
- `INSERT INTO 表名 (列1, 列2, ...) VALUES (...), (...);`——值和列一一对应；文本用**单引号**，数字不加引号；多行之间逗号，整句末尾分号。

## 示例查询

选中某一句再按 `Ctrl + Enter`，就只执行那一句。

**查询 1：看整张表**

```sql
SELECT * FROM travel_claims;
```

`SELECT` = 取数据；`*` = 所有列；`FROM travel_claims` = 从这张表取。结果 7 行 7 列。

**查询 2：只看需要的列，并按自己想要的顺序排列**

```sql
SELECT trip_date, name, amount FROM travel_claims;
```

列的顺序就是你写的顺序。核查时常把日期放最前，方便和别的表对日期。

**查询 3：数行数**

```sql
SELECT COUNT(*) FROM travel_claims;
```

结果 `7`。拿到台账先数笔数，和对方报的“共 7 笔”对得上，再往下做。

**查询 4：给结果列起个中文名**

```sql
SELECT name AS 姓名, amount AS 金额 FROM travel_claims;
```

`AS` 只改结果里显示的列名，不改表本身。导出给别人看时很方便。

**查询 5：看表结构**

```sql
PRAGMA table_info(travel_claims);
```

列出每一列的名字和类型，`pk = 1` 的是主键。忘了列名时用它查。

## 练习（由易到难）

1. 查出 `travel_claims` 的全部内容。
2. 只查报销单号、姓名、金额三列，并把这三列显示为“单号”“姓名”“金额”。
3. 补登一笔：单号 2008，庚七兰，工号 `E-0107`，综合科，2026-04-28，北岭市，1120 元。插入后数一数，应为 8 笔。
4. 再执行一次第 3 题的 `INSERT`，会发生什么？读一读报错信息，用一句话说明它为什么是“好事”。
5. 贴近实际：新建 `leave_records`（请假登记表），四列：`leave_id`（整数，主键）、`emp_no`（文本）、`name`（文本）、`leave_date`（文本），插入下面 3 行：
   - 1，`E-0102`，乙二红，2026-04-08
   - 2，`E-0104`，丁四强，2026-04-16
   - 3，`E-0103`，丙三华，2026-04-22

   然后分别查出报销台账的 `emp_no, name, trip_date` 和请假表的 `emp_no, name, leave_date`，**用眼睛比对**：谁在请假当天报了出差？丁四强算不算？为什么比对时要“工号 + 日期”两样都对上？

## 常见错误

- **中文标点**：`，` `（` `‘` 会报 `syntax error`。SQL 里的符号一律英文半角，引号里面的中文内容没关系。
- **最后一列后面多逗号**：`amount REAL,)` 报错。
- **文本没加引号**：`VALUES (2008, 庚七兰, ...)` 会报 `no such column: 庚七兰`——没加引号的字被当成了列名。
- **列数和值数对不上**：7 个列名配 6 个值，报 `7 columns but 6 values were supplied`，数一数逗号。
- **主键重复**：报 `UNIQUE constraint failed`。
- **忘了 Write Changes**：关掉软件，数据就没了。

4. 报错 `UNIQUE constraint failed: travel_claims.claim_no`。单号是主键，不允许重复，所以同一张单子登两次会被直接挡住。手工 Excel 台账里“一单两报”要靠人眼去发现，数据库在录入时就拦住了。

```sql
DROP TABLE IF EXISTS leave_records;

CREATE TABLE leave_records (
    leave_id    INTEGER PRIMARY KEY,
    emp_no      TEXT,
    name        TEXT,
    leave_date  TEXT
);

INSERT INTO leave_records (leave_id, emp_no, name, leave_date) VALUES
    (1, 'E-0102', '乙二红', '2026-04-08'),
    (2, 'E-0104', '丁四强', '2026-04-16'),
    (3, 'E-0103', '丙三华', '2026-04-22');

SELECT emp_no, name, trip_date FROM travel_claims;
SELECT emp_no, name, leave_date FROM leave_records;
```

比对结果：

- **乙二红**（E-0102）：4 月 8 日请假，同一天报了云溪市出差 980.5 元（单号 2002）——疑点。
- **丙三华**（E-0103）：4 月 22 日请假，同一天报了云溪市出差 1405 元（单号 2006）——疑点。注意他 4 月 10 日那笔没问题，所以不能只看“名字出现在两张表里”。
- **丁四强**（E-0104）：出差 4 月 15 日，请假 4 月 16 日，日期不同，**不算**。

为什么要“工号 + 日期”：只比工号，丙三华的两笔会被一起标出来，误伤正常的那笔，丁四强也会被误标；只比日期，会把同一天请假和出差的不同人凑到一起。两样都对上才是同一个人、同一天。

预告：以后一句话就能筛出来（今天不要求看懂）：

```sql
SELECT t.name, t.trip_date, t.amount
FROM travel_claims t
JOIN leave_records l
  ON t.emp_no = l.emp_no AND t.trip_date = l.leave_date;
```

## 加练：换一个场景再做一遍（补贴名单比对）

> 同一课的另一套讲解和练习，场景是补贴发放名单和在职人员名单。正课学完还有余力再做。

### 本课目标

1. 说清楚数据库、表、行、列分别是什么。
2. 会用 `CREATE TABLE` 建表，知道 SQLite 常用的三种类型 `INTEGER`、`REAL`、`TEXT`。
3. 会用 `INSERT INTO` 插入数据，用 `SELECT * FROM` 把表查出来。

### 讲解：用 Excel 来类比

设想你手上有一份《补贴发放名单》Excel，要和另一份《在职人员名单》核对，看有没有人“既领补贴又在编”。

| Excel 里 | 数据库里 | 说明 |
|---|---|---|
| 整个工作簿（.xlsx 文件） | **数据库**（database，SQLite 里就是一个 `.db` 文件） | 装很多张表 |
| 一个工作表（sheet） | **表**（table） | 一类事物一张表：补贴名单一张、在职名单一张 |
| 一行 | **行**（row / record，记录） | 一个人、一笔发放 |
| 一列 + 列标题 | **列**（column / field，字段） | 姓名、证件号、金额…… |

和 Excel 最大的区别：**数据库的每一列在建表时就规定好类型**。“金额”列规定是数字，就不会混进“一千二”这样的文字；“证件号”规定是文本，开头的 0 不会被吃掉——这两件事在 Excel 里都是核查时的常见坑。

SQLite 最常用三种类型：

- `INTEGER`：整数（序号、人数）
- `REAL`：小数（金额）
- `TEXT`：文本（姓名、证件号、日期——SQLite 的日期统一写成 `'2026-03-05'` 这种文本）

**主键**（`PRIMARY KEY`）：每张表挑一列当“身份证”，每行的值都不同、不能重复。今天用一个简单的序号 `id` 当主键。

### 建表加数据脚本

打开 DB Browser → 打开昨天建的 `practice.db`（没有就 *New Database* 新建一个）→ 切到 **Execute SQL** → 粘贴整段 → `Ctrl + Enter`。

```sql
-- 第 1 课：补贴发放名单（数据全部虚构）
DROP TABLE IF EXISTS subsidy_list;

CREATE TABLE subsidy_list (
    id        INTEGER PRIMARY KEY,   -- 序号，主键
    name      TEXT,                  -- 姓名
    id_no     TEXT,                  -- 证件号（虚构格式）
    town      TEXT,                  -- 乡镇
    amount    REAL,                  -- 发放金额（元）
    pay_date  TEXT                   -- 发放日期
);

INSERT INTO subsidy_list (id, name, id_no, town, amount, pay_date) VALUES
    (1, '赵小一', 'XN-0000-0001', '青石镇', 1200,  '2026-03-05'),
    (2, '钱小二', 'XN-0000-0002', '青石镇', 800,   '2026-03-05'),
    (3, '孙小三', 'XN-0000-0003', '白沙乡', 1500,  '2026-03-06'),
    (4, '李小四', 'XN-0000-0004', '白沙乡', 600.5, '2026-03-06'),
    (5, '周小五', 'XN-0000-0005', '红柳镇', 1200,  '2026-03-07'),
    (6, '吴小六', 'XN-0000-0006', '红柳镇', 950,   '2026-03-07');
```

执行后点 **Write Changes** 保存。切到 **Browse Data** 页，选 `subsidy_list`，能看到 6 行，像一张 Excel 表。

逐句看：

- `DROP TABLE IF EXISTS subsidy_list;`——如果已有同名表就先删掉。这样脚本可以反复运行，不会报“表已存在”。
- `CREATE TABLE 表名 ( 列名 类型, ... );`——建表。列之间用逗号隔开，**最后一列后面不加逗号**。
- `INSERT INTO 表名 (列1, 列2, ...) VALUES (值1, 值2, ...), (...);`——插入数据。值的顺序和前面列的顺序一一对应；文本用**单引号**，数字不加引号；多行之间用逗号，整句最后一个分号。
- `--` 后面是注释，SQL 不执行，用来写说明。

### 示例查询

在 Execute SQL 页，**选中某一句再按 `Ctrl + Enter`**，就只执行选中的那句。

**查询 1：看整张表**

```sql
SELECT * FROM subsidy_list;
```

`SELECT` 表示“我要取数据”，`*` 表示“所有列”，`FROM subsidy_list` 表示“从这张表取”。结果：6 行 6 列。

**查询 2：只看几列**

```sql
SELECT name, town, amount FROM subsidy_list;
```

把 `*` 换成列名，列名之间逗号隔开。结果只有姓名、乡镇、金额三列，顺序就按你写的顺序。（下一课专门讲 SELECT。）

**查询 3：数一数有几行**

```sql
SELECT COUNT(*) FROM subsidy_list;
```

`COUNT(*)` 数行数，结果是 `6`。拿到一份新名单，先数行数是核查的第一步——和对方说的人数对不上，后面就不用往下做了。

**查询 4：看表结构**

```sql
PRAGMA table_info(subsidy_list);
```

`PRAGMA` 是 SQLite 特有的命令，列出每一列的名字和类型（`pk` 为 1 的那列是主键）。忘了列名叫什么时用它查。

   - 101，冯甲，`XN-0000-0101`，虚构局办公室

### 常见错误

- **中文标点**：`，` `（` `‘` 会报 `syntax error`。SQL 符号一律英文半角，文本内容里的中文没关系。
- **最后一列后面多了逗号**：`pay_date TEXT,)` 会报错。
- **文本忘了加引号**：`VALUES (7, 郑小七, ...)` 会报 `no such column: 郑小七`——SQL 把没加引号的字当成了列名。
- **用了双引号包文本**：SQLite 有时能容忍，但标准写法是单引号，养成习惯。
- **主键重复**：再插一次 `id = 1` 会报 `UNIQUE constraint failed`。这正是主键的作用。
- **忘了 Write Changes**：关掉软件后数据没了。
