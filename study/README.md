# 每日课表：运行说明

这份说明写给每天早晚自动运行的两个定时任务，也方便以后自己查。课程安排在 `src/plan.js`，进度在 `study/progress.json`，每天的讲义在 `study/daily/`。

## 进度怎么走

- 课程按顺序推进，不和日期绑死。`progress.json` 的 `next` 记着每科下一课的序号（从 0 开始）。
- 早上推送时，按“周几的时段安排 + 各科下一课”算出当天内容，记进 `days[日期].planned`。
- 晚上打卡时，只有打了“完成”的科目才前进一课。没学完的课，下一次排到这科时接着学。
- 英语不单列课程：每天跟着当天 CFA 课的英文主题学术语；周日做本周词汇小测。

## 命令

```bash
node study/today.js                  # 看今天（北京时间）的安排
node study/today.js 2026-10-12       # 看某一天
node study/today.js --record         # 早上用：把今天的安排记进 progress.json
node study/checkin.js 2026-10-12 --done sql,cfa,en --minutes 90 --note "……"
node study/checkin.js 2026-10-12 --done all
node study/checkin.js 2026-10-12 --done none
python3 build.py                     # 改完进度后重新生成 index.html
```

科目代号：`en` 英语，`sql` SQL，`py` Python，`cfa` CFA 一级，`geo` 地缘政治，`rev` 周复盘，`prep` 准备日。

## 早上 7 点：生成当天讲义

1. `git pull`，然后运行 `node study/today.js --record`，拿到当天的时段和课题。
2. 看前一天的记录：如果还是 `pushed`（没打卡），讲义开头提醒一句“昨天没打卡，按没学处理，今天接着学同一课；如果其实学完了，回复一句我来补记”。如果前一天的 `note` 里有没弄懂的问题，开头先用一小段讲清楚。
3. 按下面的“讲义写法”写 `study/daily/<日期>.md`。
4. `python3 build.py`，提交并推送（提交信息如“每日讲义 2026-10-12”）。然后按下面“同步到研习录云端版”更新进度。
5. 给用户发一条消息：今天几个时段、各学什么、合计多少分钟，附讲义链接 `https://github.com/cnyanghai/yanxilu/blob/main/study/daily/<日期>.md`。用户如果在这次会话里提问，就地解答。

## 晚上 9 点：打卡

1. `git pull`，读当天的 `planned` 和讲义。
2. 给用户发消息，逐项列出今天的时段，请他回复：哪些学完了、大概用了多久、哪里没懂。给一个回复示例，如“英语、SQL 完成，CFA 没做，用时 70 分钟，WHERE 和 HAVING 还是分不清”。
3. 收到回复后：运行 `checkin.js` 记录；把没懂的地方当场讲清楚，并把问题写进 `--note`，第二天讲义开头再回顾一次；`python3 build.py`，提交并推送（“打卡 2026-10-12”）。
4. 按下面“同步到研习录云端版”更新进度，并在 `journal` 集合加一条学习足迹：id 为 `j-<日期去横线>-daily`，内容 `{ date, minutes, ref: "plan", text, t }`，`text` 写“每日课表：完成 英语、SQL；……”加上用户说的收获或问题。没学的日子不记足迹。
5. 连续两天以上没打卡或没学，语气平和地问一句是不是时间排不开，需要的话把每天的量调小，而不是一直堆积。

## 同步到研习录云端版

研习录的主用版是 claude.ai 上的 Artifact（https://claude.ai/artifact/LpwLZchfacKZAnJs577MvM ），课表页从它的数据库读进度，不需要重新发布页面。每次 `progress.json` 变了之后：

1. 用 ArtifactData 工具（先用 ToolSearch 加载）`get` 集合 `study`、文档 `progress`，记下返回的 `version`。
2. 再 `set` 同一文档，`file_path` 指向 `study/progress.json`，`if_version` 填上一步的版本号。
3. 学习足迹写在集合 `journal` 里，新建文档不用 `if_version`。

工具不可用就跳过这一步，GitHub 上的公开版照样是最新的。只有改了页面代码（`src/` 下的文件）才需要用 Artifact 工具重新发布 `dist/artifact.html`。

## 讲义写法

讲义用中文写，术语保留英文。整份讲义要能直接照着学完，不需要另找材料。

- **开头**：今天的时段表（科目、分钟、课题）；昨天的问题回顾（如果有）。
- **英语（20 分钟）**：10 个和当天 CFA 主题相关的术语（英文、音标、中文、一句英文例句和译文）；一篇 120–180 词的英文短文（自己写，主题同当天 CFA 课）和 3 道理解题；列出 1、3、7 天前讲义里的术语（只列英文，让他自己回想中文）。周日改为本周词汇小测 20 题。
- **SQL（45 分钟）**：本课目标；用他熟悉的筛查、比对场景讲概念；一段能直接粘贴到 DB Browser for SQLite 运行的建表加数据脚本；3–5 个示例查询，逐行解释；5 道练习，由易到难，最后一道贴近实际工作；常见错误；答案放在文末的 `<details>` 里。
- **Python（45 分钟）**：本课目标；讲解；能直接在 Jupyter 里运行的代码单元，需要的 Excel 用代码现场生成，不依赖外部文件；5 道练习，答案放在 `<details>` 里。
- **CFA（35 分钟）**：本课对应模块的学习目标；讲解；公式和计算例题（写出计算器步骤）；5 道仿一级考试格式的三选一选择题，答案和解析放在 `<details>` 里。
- **地缘政治**：周六说明读原书哪一章、哪几节，给出研习录精读页的入口（https://claude.ai/artifact/LpwLZchfacKZAnJs577MvM ），列 3 道思考题。周日联网找一件最近一周的国际时事，给出用这一章框架分析的写作提示（写 300 字左右）。只用自己的话概括书的观点，不大段摘录原文。
- **周复盘（50 分钟）**：本周打卡统计；SQL、Python、CFA 小测各 5 题（答案折叠）；列出本周没完成的课；一个 20–30 分钟的小实战，用本周学的 SQL 或 Python 处理一份现场生成的模拟数据。
- **结尾**：今晚 9 点打卡要回答的三个问题。

**模拟数据一律虚构**：姓名用明显虚构的名字，身份证号、账号等用虚构的格式，不要出现任何真实的人、单位或案件。
