# 研习录 · 版本 2 · 我们怎么做决定（2026-10-30）

用户没有游戏和三维制作的经验，面对"程序风格、叠楼还是小镇、烘焙还是引擎"这类提法，没法有把握地拍板。这页定一套办法，让用户只在**看得见、感觉得到**的事情上做决定，技术决定由 Claude 做并记录，用结果来验证。

## 1. 分工

- **用户是导演和甲方**：管愿景、管品味、管验收。决定的对象永远是一张图、一段动效、一次上手体验，不是一个术语。
- **Claude 是制作方**：管所有技术决定（引擎、格式、管线、结构），每个决定要可逆、要记录、要说清楚对用户看得见的东西有什么影响。做错了换掉，不需要用户为它负责。
- **外援只请一种人**：真正需要品味的手艺活（主角家具、look-dev）请三维美术师按件做；不请架构师。

## 2. 愿景先落成看得见的东西

用户的设想现在散在 `BRIEF.md` 的十条回答和几次对话里。要把它变成两样可以对着检查的东西：

**愿景板**（`design/VISION-BOARD.md`，下一步由 Claude 起草，用户只改不写）：
- 五张"就是这个感觉"的图：kriss 的咨询室、概念图 B、夜读概念图、igloo 的一帧、用户自己再挑一两张。
- 三张"绝不是这个"的图：后台管理系统、电商页、PPT 风的三维。
- 每一间一句话：书房是什么感觉，花房是什么感觉。
- 一句总的：研习录是一间可以养的书房，你剪的、读的、写的在里面长成东西，别人也能进来看。

**验收单**（十条，每条都能用眼睛和手回答"是 / 否"）：
1. 打开第一眼像一间模型屋，不像一个网页。
2. 不用任何说明文字就知道能点哪里。
3. 点进去、退出来，眼睛不晕。
4. 手机上一样能用，拇指够得到。
5. 看一眼就知道今天该读什么，没有红点、没有催。
6. 读过的痕迹留在物上（书口进度、宝石、抽出半截）。
7. 三种光切换，东西不变、只有光变。
8. 空的第一天也好看，五百本书的时候也好看。
9. 第一屏三秒内出来（国内网络、普通手机）。
10. 和 kriss 并排放，不丢人，而且一眼看出不是 kriss。

每一步的产物都拿这十条过一遍，用户只打勾。

## 3. 每个决定怎么摆到用户面前

Claude 提任何需要用户定的事，必须带四样：
- **可看的样子**：两到三个版本的图或短动效，不是文字描述。
- **一句话推荐**：我选哪个，为什么，用生活语言说。
- **代价**：多少时间、多少钱、以后改要付什么。
- **可逆性**：改主意的成本是大是小。

用户三种回答都行：选一个；"你定"；"都不对，我要的是……"。第三种最有价值，说不清楚就指着图说"更像这张"。

看不见的决定（引擎、文件格式、烘焙参数、代码结构）不拿给用户，Claude 直接定，写进 STATUS 的"已定决策"，只告诉用户它带来的后果（比如"手机上会快一倍"）。

## 4. 节奏：每一步都出图，每周对一次愿景板

- 任何一步的交付物首先是**图**（静帧、对照图、线上截图），其次才是代码。没有图的进展不算进展。
- **对照墙**：每次出图都和目标图、kriss 的同机位并排放，用户给六项打一到五分：形体、材质、光、密度、生命、整体感。分数不涨就停下来找原因，不往前堆功能。
- 每周一次回看愿景板和验收单，看方向有没有跑偏；跑偏了先改愿景板再改东西。
- 里程碑一定在**用户自己的手机和电脑上**看，不只看截图。
- **外人的眼睛**：每个里程碑给两三个没看过项目的人看十秒，问"这是什么"。答"一间书房 / 一个模型屋"算过，答"一个网站 / 一个游戏"算不过。

## 5. 止损

- 一个方向两轮图还不像，换方向，不加第三轮。
- 一件资产 AI 出三次还不行，改程序化或请人做，不出第四次。
- 任何一步超过预估时间一倍，停下来重新估，不硬顶。

## 6. 现在就定的事

过去两天那些提法，用户不需要逐条拍板。按这页的规矩，它们都属于"看不见的决定"，Claude 已经按推荐定下并写进了 STATUS，都是可逆的：

- 运行时照 kriss、资产照农场视频的生产线、三层结构；小镇式铺开；烘焙的三维；不请架构师。
- 用户只定看得见的：主线风格走概念图 B 的方向（墨色家具、纸白墙、浅木地板），默认晴窗，镜头长焦在房外。这三条是用户已经看过图定的。

下一步只需要用户做一件事：看 Claude 起草的愿景板和验收单，改到"对，就是这样"为止。之后每一步用户只看图、打分、打勾。
