## 风格：做成风格包，先从 kriss 式现代书房开始

用户提出：kriss 的城市办公风、炉石的酒馆风、魔法书院风、宋朝田园小院风以后可能都要做并放进商店，先从 kriss 式开始。Claude 的判断：**同意先做 kriss 式**，理由和代价如下。

同意的理由：
1. 现代简约是四种里最容易生产的：几何简单、材质少、CC0 现代家具最多、图生三维对现代家具效果最好。用它先把"一个风格包里有什么"跑通，后面的包照着套。
2. 有看得见的标杆：对照墙有 kriss 的图可以打分，其他三种风格没有同级别的参照。
3. 多风格进商店，意味着风格必须是可整套替换的"包"。这正是 MASTER-PLAN 预留的机制，现在提前兑现。

代价：
1. 概念图 B 方向（纸木墨铜中式）和这两天的概念图搁置，归入第二个包"宋朝田园小院"，不作废。
2. 项目的"气质"要从"纸木墨铜"改写成风格无关的东西：不变的是结构（书墙、笔记本架、案头、院子）、交互和数据，变的是壳、家具、材质、光、界面色。BRIEF 在阶段 1 重写。
3. 临摹的是"现代简约办公书房"这个风格类别，不是 kriss 的具体设计：不用他们的模型、贴图、配色表、房型。

风格包的顺序：1 现代书房（kriss 式）→ 2 宋朝田园小院 → 3 酒馆 → 4 魔法书院（不用任何 IP）。

## 视角与操控（第三稿，2026-10-30 用户定：在场为底，对焦为点）

用户提出用暗黑的游戏设计思维重新梳理：暗黑不分几级镜头，镜头跟着人物，一个键在原地放大。下面是两种做法的对比和 Claude 的推荐。

| | kriss 式「展柜」 | 暗黑式「在场」 |
|---|---|---|
| 世界是什么 | 一件被捧在手里的物品，从外面看进去 | 一片连续的地面，你站在里面 |
| 镜头 | 几个固定机位（院子 / 整间 / 案头），点一下飞过去 | 一个镜头永远跟着你的角色，固定俯角、不转；一个键原地放大一级 |
| 角色 | 可有可无，是摆设 | 必须有，永远在画面中央，一切操作都是"走过去、点一下" |
| 操控 | 点热点、滚轮、面包屑 | 点地面走过去，点物件走过去并打开（暗黑本来就是单指操作，手机天然合适） |
| 房间的墙 | 剖开的盒子，朝镜头的墙不存在 | 没有屋顶，挡住角色的墙淡掉或降矮（暗黑、模拟人生都这样） |
| 社交 | 像看别人的橱窗 | 走进别人的院子，走到留言板前留言 |
| 商店与摆放 | 换槽位里的东西 | 建造类游戏的标准做法，自由摆放顺理成章 |
| 养成 | 看状态 | 走到猫跟前摸一下、走到花前浇水 |
| 技术多出来的 | 无 | 寻路（用放置用的格子就行）、角色控制、跟随镜头、遮挡淡出、可移动角色的光（已决定用光探针加接触阴影） |
| 代价 | 没有"身在其中"，社交和建造都别扭 | 阶段 3 多一到两周；角色质量变成门面；每次读书要走过去 |

**一个真正的冲突**：暗黑的俯角高（约 45 到 55 度），看的是地面布局；我们的核心内容书墙、笔记本架是竖着的面，俯角高了书脊读不出来。暗黑的解法是重要的竖面放在屏幕上方、朝向镜头的那面墙上；我们还要再加一步。

**推荐：在场为底，对焦为点。** 平时是暗黑式：角色在房里走，镜头跟随，俯角取中间值约 40 度，放大键原地推近一级。走到书墙、笔记本架、案头这三处点一下，镜头从跟随切到一个对焦机位（就是 kriss 那种低俯角、长焦、看清每一本），这时角色退到画面边上；再点书，取下来是牌，打开是阅读器面板。按 Esc 回到跟随。一句话：**走进去，看得清。**

这样 kriss 的几级镜头没有丢，变成了两类：跟随镜头的两级放大（院子 / 房间），和三个对焦站（书墙 / 笔记本架 / 案头）。地址仍然可以直达：`#/study/shelf` 等于把角色传送到书墙前并进入对焦。

**读书的快捷路径**：点书墙上的任何一本书，角色自动走过去、到位即对焦并取下那本，一次点击完成，不比现在多一步。手机上点不准就先进对焦站再点。

**对计划的影响（若采纳）**：
- 阶段 1：主视觉第二轮改成"游戏画面"的取景，角色站在房间中间，镜头 40 度俯角、长焦，墙在远侧；顺带把角色换成皮克斯式。两张约 0.75 元。
- 阶段 2：角色权重上升，四视图加走、站、坐、取书、摸猫五个动作示意；房间平面图要按格子画。
- 阶段 3：加点地走路、格子寻路、跟随镜头与两级放大、三个对焦站、墙淡出；时间盒从两周改三周。
- 引擎不变。这些在 three.js 里都是成熟做法。

**结果**：用户 2026-10-30 定"在场为底，对焦为点"。上面"对计划的影响"全部生效。

## 由此推出的技术结论（Claude 定，写在这里让你看见）

- 引擎不变：自带 three.js、烘焙的三维、不引框架。以上范围没有一项需要换引擎。
- 角色改成游戏式三维人物后，需要骨骼动画：three.js 的 SkinnedMesh 与 AnimationMixer，模型来源是 CC0 角色或图生三维后自动绑骨（Mixamo 一类），动作用现成动作库。比纸人的程序化动画重，但是成熟路线。
- 卡片里的三维形态：一张卡一个小的三维视口，共用一个渲染器分区绘制，不是每张卡开一个 WebGL。
- 商店与库存：新集合 `items`（商店目录）、`inventory`（买到的）、`placements`（放在哪个槽位），服务器版存 Baba，公开版存 localStorage。
- 风格包的定义：壳模型 + 家具集 + 材质与贴图 + 三种光的烘焙 + 界面色表，一个目录一个包，槽位名在所有包里一致。
- 阅读和笔记正文仍是版本 1 的二维页面，三维只做入口与动画。
