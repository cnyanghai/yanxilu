# 部门提案 06 · 工具程序兼后端程序（2026-10-30，第一轮）

署名：工具程序 / 后端程序（Claude 分岗）。依据：暗黑 2 与红警都是工具先行，内容是用编辑器摆出来的，不是用代码写出来的；暗黑 2 的预设是 JSON 实体组件，红警的规则是 INI 表。

## 1. 我看到的问题

1. **没有编辑器，摆放靠改代码。** 五件 Rodin 家具的位置写死在 `world/world.js` 的 `VERIFY_SLOTS` 里，读书椅挪到窗边改了一次代码、重跑一次截图。暗黑 2 一块城镇 1639 个实体，没人是写代码摆的。
2. **烘焙一轮 8 分钟且无增量。** 改一个斜面板的角度也要三种光六张图全烘；今天为此等了三轮。`bake_study.py` 没有"只烘改过的组"，三种光串行。
3. **资产没有导入管线。** Rodin 出的 glb 靠我手敲 gltf-transform 命令，面数、尺寸、贴图大小没人校验，桌子三轴拉伸、凳子代替椅子都是肉眼发现的。`ASSET-SPEC.md` 第 4 节的六条交付定义没有一条是机器检查的。
4. **表没有编辑与校验。** `study.json` 是烘焙顺手写出来的，`items / inventory / placements` 还没有定义；没有 Schema，字段写错要到运行时才发现。
5. **后端没有商店与社交的接口。** Baba 的 `/api/yxl/*` 只有 state / files 这类通用读写，没有商店目录、库存、摆放、舒适度、参观、留言；集合名 `COLLS` 里也没有这些。
6. **截图测试跑在软件渲染上。** swiftshader 没有各向异性、帧率低到和烘焙并行就超时；对照墙的画质本身就比真机差一档，打分不准。

## 2. 我的主张

1. **摆放编辑器最小版，两周内可用。** 在 `/world` 里按反引号进工坊后再按 E 进编辑模式：点选任一可移动物件（Rodin 家具、商店物件），按住拖动时按 0.5 米格子吸附，R 旋转 90 度，Delete 收回，放置时非法（越界、重叠、槽位类型不符）变红不落地；Ctrl+Z / Ctrl+Y 撤销重做（命令栈）；S 保存。保存的就是 `placements` 记录：`{item, x, y, rot, surface, slot?}`，公开版写 localStorage，服务器版 `PUT /api/yxl/placements`。同一套编辑器也用来摆风格包的固定家具，输出 `world/packs/<pack>/preset.json`，格式照暗黑 2：`entities[] → components[]`（Transform、Model、Light、Collider、Hotspot）。
2. **一切表都有 Schema 和校验脚本。** `data/schema/` 下放 `items.schema.json`、`placements.schema.json`、`objects.schema.json`（交互物件：状态、动画、操作函数名）、`rooms.schema.json`、`vis.schema.json`、`preset.schema.json`、`props.schema.json`（每包的道具调色板）。`tools/tables_check.py` 校验全部表并进 `world_test.py` 的前置步骤；字段改名、引用了不存在的模型、槽位类型拼错，在提交前就红。
3. **资产导入一条命令。** `tools/asset_import.py <glb或图片> --kind furniture --id desk --w 1.6 --h 0.76 --d 0.7`：图片则先走 Rodin；然后 gltf-transform 减面到预算（家具 3000、道具 500、角色 8000）、weld、贴图转 KTX2 或 1024 JPG、自发光贴图搬到 baseColor（Rodin Shaded 的坑）、原点落地正面 -Z、按尺寸表校验包围盒 ±5%、生成接触阴影贴片参数、写入 `world/packs/<pack>/furniture/<id>.glb` 并在 `props.json` 登记一行、出一张同机位截图进对照墙目录。任何一步不过就拒绝入库并说明原因。这就是 ASSET-SPEC 第 4 节六条的机器版。
4. **烘焙增量与并行。** `bake_study.py` 按组和光分任务：`--groups shell,furn --lights day`；每组记录输入哈希（几何与材质参数），没变就跳过；三种光各起一个 Blender 进程并行（Windows 显卡显存够），预计 8 分钟降到 3 分钟以内，改一个板子 1 分钟。壳按面拆贴图（灯光师 / 技术美术的要求）后，每面一张图也是一个任务。
5. **截图测试改真显卡。** 测试脚本改成可连 Windows 侧的 Chrome（远程调试端口），跑不起来再回退 swiftshader；对照墙、回归、分档（手机 0 档）三套截图都走它，并把结果存成 `tools/out/wall/<日期>/`，一个 `make_wall.py` 拼墙。以后每次提交 main 自动跑一遍（GitHub Actions 只跑表校验与语法，截图在本机，因为显卡在本机）。
6. **后端接口清单与数据模型。** 新集合全部按"表"建：
   - `items`（商店目录，只读，由仓库 `props.json` 生成）、`inventory`（用户买到的：item、数量、买入时间）、`placements`（摆在哪）、`comfort`（舒适度快照：基础 + 多样性 + 质量 + 增益，按天算一次）、`visits`（谁来过）、`notes`（留言：来访者、文本、留在哪个物件上）、`wallet`（货币：读书与结卷攒的）。
   - 接口：`GET /api/yxl/shop`、`POST /api/yxl/buy`、`PUT /api/yxl/placements`、`GET /api/yxl/comfort`、`GET /api/yxl/visit/<user>`（返回对方的 placements 与公开的书墙快照，不含正文）、`POST /api/yxl/note`。都走现有的 cookie 会话与 `put / del` 语义，复用 Baba 的通用 state 存储，不新开数据库。
   - 部署流程不改：仍是推 main 上线静态、Baba 代码由人跑 `scripts/deploy-yanxilu.sh`；但接口先在 `tools/baba_mock.py` 里实现一遍，前端对着 mock 开发，Baba 那边一次性照抄。

## 3. 我需要什么

- 引擎程序定下 `preset.json` 与 `placements` 的最终字段（我出草案，一天内要回复），以及可移动物件在场景里的统一包装（一个 `Placeable` 类：模型、包围盒、槽位类型、状态机）。
- 关卡设计师给出槽位类型与合法性规则的表（地面 / 靠墙 / 桌面 / 架上 / 窗台 / 墙面，占地格数，能否叠放）。
- 美术 / 技术美术确认面数与贴图预算（我按 ASSET-SPEC 第 3 节写进校验，改了要同步）。
- 系统设计师给舒适度公式与货币来源，我才能写 `comfort` 与 `wallet`。
- Windows 侧 Chrome 开远程调试端口的权限（用户在 Windows 上起一次）。

## 4. 怎么验收

- 编辑器：不改一行代码，把五件家具摆成主视觉 B 的布局并保存，刷新后原样；撤销十步不丢；非法位置放不下去。
- 表校验：故意写错一个槽位类型，`tables_check.py` 失败并指出行与字段。
- 导入管线：一张椅子图片一条命令进包，面数 ≤ 3000、包围盒在 ±5%、贴图 ≤ 1024、截图自动出现在对照墙。
- 烘焙：改一个家具参数后再烘，只烘 furn 组，三种光并行，总时长 ≤ 3 分钟。
- 真显卡截图：同一机位的截图各向异性与抗锯齿可见，和手机真机对比不失真。
- 后端：mock 上跑通买一件、摆一件、算一次舒适度、别人来参观并留言的完整链路，再部署 Baba。

## 5. 与其他岗位的接口

- 引擎程序：预设与摆放 JSON 的格式、`Placeable` 包装、编辑模式的输入接管。
- 关卡设计师：用编辑器摆房间与院子，不写代码；槽位规则表归他维护，我校验。
- 美术 / 技术美术：资产交付定义变成导入命令的检查项；对照墙目录与命名由我提供。
- 系统设计师：舒适度公式、货币、商店定价进表，我提供表与接口。
- 测试：真显卡截图与表校验接进回归；设备矩阵由测试定。

## 6. 第一个交付物与代价

**第一个交付物：表的 Schema 加校验脚本，加摆放编辑器最小版（拖动、吸附、旋转、保存、撤销）。** 检验：按第 4 节前两条。代价 0 元，约 4 个工作日（Schema 与校验 1 天，编辑器 3 天）。随后依次：导入管线 2 天、烘焙增量并行 1 天、真显卡截图 1 天、后端 mock 接口 2 天。合计约 10 个工作日，不花钱。

一句话：先把"摆东西不用改代码、入资产不用肉眼查"这两件做出来，后面每个岗位的产能都翻倍。
