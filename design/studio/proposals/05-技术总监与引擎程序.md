# 部门提案 · 技术总监兼引擎程序（2026-10-30，第一轮）

署名：技术总监 / 引擎程序（Claude 分岗）。只对运行时、数据结构、性能和测试负责；画面好不好看归美术总监与灯光师，我负责让他们要的东西跑得动。

## 1. 我看到的问题

- `world/world.js` 已到 645 行一个文件：场景搭建、书盒生成、镜头、路由、拾取、工坊、验证开关全在一起。再加寻路、角色、状态机、后期、分档，会到两千行，没人能改。
- **机位与数据耦合**：`study.json` 里机位、槽位、尺寸、贴图名混在一张配置里，由 Blender 脚本导出；改一个机位要重烘。路由表 `ROUTE_SHOT` 写死在代码里。
- **没有表**：家具、槽位、物件、光都是代码常量或 Blender 导出物。暗黑 2 的做法是 364 张表加实体-组件 JSON，代码只读表；我们连一张都没有。
- **没有实体-组件**：书、盒、牌、灯各自一段专用代码，加一种物件就加一段。
- **没有后期管线**：画风后期是硬塞进 `frame()` 的一个分支；雾、暗角、调色、泛光没有地方放。
- **没有分档**：手机和桌面跑同一套；真机（微信内置浏览器）没测过。
- **测试慢且脆**：swiftshader 软件渲染截图一轮两三分钟，与烘焙同时跑就超时；没有表加载、寻路、状态机的单元测试；回归只看 draw call 和控制台报错。

## 2. 我的主张

**主张一：分三层四目录，文件按层切，单文件不超过 300 行。**

```
world/data/      数据层：四张表 + 包清单 + 存档读写（S.data 适配）  —— 纯 JSON 与纯函数，可单元测试
world/sim/       世界层：格子、寻路、角色状态、物件状态机、舒适度、时间与天气  —— 不 import three
world/render/    渲染层：场景装配、材质、光与 vis、后期、镜头、拾取、分档
world/app.js     装配：读表 → 建世界 → 建渲染 → 路由与输入
```
世界层每 50 毫秒一拍（暗黑的 25 帧逻辑），渲染层按屏幕刷新率插值。两层之间只传事件和快照，这是以后社交同步和版本 1 回退界面能成立的前提。

**主张二：实体-组件 JSON，第一版只要七个组件。** Transform、Model（文件、档位、是否投影）、Slot（放在哪个槽位、占地）、Interact（状态机名、操作函数名、热区）、Light（点 / 聚、颜色、功率、半径、是否投影）、Data（绑定到 S.data 的集合与 id）、Tier（可见档、阴影档）。预设 = 实体数组；包 = 预设 + 资产清单。不做通用 ECS 框架，组件就是对象上的字段，系统就是几个循环。

**主张三：四张表，字段现在就定，加载走一个 `loadTables()`。**
- `objects.json`：id、模型、状态机（neutral / operating / opened 各一个动画名）、operateFn、selectable、collision、light（可选）、tier。
- `rooms.json`：id、尺寸与格子、槽位列表（名、类型、格、朝向）、默认 vis、对焦站机位、相邻房间与门。
- `vis.json`：按房间 × 时段：exposure、keyLight（功率、色、方向）、fill、fog（色、密度）、lut、vignette、characterLight（功率、半径）。
- `props.json`：按包：物件 id → 模型与贴图文件、变体权重、面数、贴图尺寸。
表由工具程序的编辑器写，运行时只读；加载时校验字段并报错到工坊面板。

**主张四：在场模式四件事的做法与代价。** 格子寻路：0.5 米格，占地由 Slot 组件写入阻挡图，A* 在世界层，房间 10 × 8 格微秒级；角色走折线再做转角圆滑。跟随镜头：目标点 = 角色位置的低通，俯角 40 度，两档距离，呼吸与视差沿用现有 rig。对焦站：复用现有 `moveTo`，对焦时跟随镜头暂停，Esc 恢复；机位进 rooms 表不再写死。墙段透明：壳在 Blender 里按墙段拆成独立网格，运行时射线从镜头到角色，命中的墙段材质 opacity 渐变到 0.15，代价是壳从 2 个网格变约 12 个，draw call 加 10。

**主张五：三档，按能力探测，不按设备型号。** 0 档（低端手机、微信）：烘焙壳 + 固定物件 + 角色，无实时阴影，无后期，贴图 1024 封顶，不加载 1 档以上物件；1 档（主流手机、笔记本核显）：加一盏带阴影的聚光、接触阴影贴片、暗角与调色；2 档（独显）：全部局部光投影、后期全开、2048 贴图。探测用 WebGL 参数与首屏三秒的帧时间，可在工坊面板手动切。

**主张六：性能预算（1 档，手机）。** draw call ≤ 120；三角面 ≤ 30 万；贴图显存 ≤ 96 MB（KTX2 压缩后）；首包 ≤ 6 MB，首屏 ≤ 3 秒（4G），其余资产按包清单流式加载；世界层每拍 ≤ 2 毫秒；60 帧目标、30 帧底线。超预算的提交自动失败。

**主张七：后期管线最小实现，不引 EffectComposer。** 场景渲到半浮点离屏图 → 一遍合成着色器做曝光、雾（按深度）、调色 LUT、暗角、颗粒、可选画风滤镜 → 屏幕。一张离屏图、一遍全屏绘制，0 档直接跳过。泛光需要再加一遍降采样，放 2 档。

**关于"不打包不引框架"：坚持不引框架，放松打包。** 分成几十个 ES 模块后，浏览器要几十次请求；用 `tools/build_world.py` 把模块拼成一个文件（不是 webpack，是几十行 Python 的拼接加版本号），开发时仍直接开源文件。three 继续自带。

**测试策略。** 世界层全部用 Node 跑单元测试（表加载与校验、寻路、状态机、舒适度计算），秒级，不开浏览器；渲染层截图改用 Windows 侧真显卡的 Chrome（Playwright 连本机 Chrome，CDP），一轮 20 秒，并且与烘焙串行排队；每张截图附 draw call、三角面、贴图内存、首包大小四个数写进对照墙。

## 4. 怎么验收

- 文件：`world/` 下没有超过 300 行的 JS；世界层目录里 `grep import.*three` 为零。
- 表：删掉代码里的 `ROUTE_SHOT`、`VERIFY_SLOTS`、`LIGHTS` 常量，全部从表来；表损坏时工坊面板显示错误而不是黑屏。
- 性能：1 档手机实测 draw call ≤ 120、首屏 ≤ 3 秒、滑动 ≥ 30 帧，数字进 STATUS。
- 测试：`node tools/tests/sim_test.js` 全绿，10 秒内；真显卡截图一轮 ≤ 30 秒。
- 三档：工坊面板切 0 / 1 / 2 档，画面与数字相应变化。

## 5. 与其他岗位的接口

- 工具程序 → 我：`rooms.json`、`objects.json`、`props.json`、预设 JSON，按本页字段；Blender 导出按墙段命名网格（`wall_back_0..n`）。
- 灯光师 → 我：`vis.json` 一行一组数；局部光作为实体的 Light 组件。两者都由渲染层直接消费，不经过代码改动。
- 美术 → 我：glb（Draco）+ 贴图（KTX2），`props.json` 里登记；面数与贴图超预算由加载器警告。
- 后端 → 我：`/api/yxl/state` 继续是数据真值；摆放 `placements` 作为一个集合存回去；社交只读别人的快照。
- 测试 → 我：对照墙截图脚本改调真显卡；预算超标即失败。
