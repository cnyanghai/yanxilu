## 2. 冲突裁决

1. **表的清单**（设计六张、技术四张、工具七张）→ 统一为七张表加两类文件：
   - `objects`（交互物件类型）、`rooms`（房：格子、槽位、默认 vis、对焦站、环境声、地标、门）、`vis`（房 × 时段）、`props`（每包资产登记）、`items`（商店目录）、`economy`（事件 → 货币）、`sound`（房 × 时段环境声、物件发声器、交互音）
   - `presets/<房>.json`：编辑器输出的固定布局（实体-组件）；`placements`：用户存档（带格式号）
   - 每张有 Schema，校验进测试前置。
2. **Rodin 怎么接光** → 灯光师的方案：PBR 模式拿 albedo，Blender 烘该物件 AO，材质 = albedo × AO，吃实时光与光探针；手绘感由 albedo 的风格化与重绘提供。自发光乘 0.55 的办法只限验证期，里程碑一内替换。生产线按美术部门的四步。
3. **房间尺寸** → 采纳 4.5 × 3.5 米（关卡、美术、第四天分析三方一致）。ASSET-SPEC 的房间行随关卡岗的平面图一起改，然后重烘。
4. **谁先谁后** → 关卡平面图（半天）→ 技术拆层与表（两天）→ 工具 Schema、校验、导入命令、烘焙增量（两天）→ 灯光第一轮（两天，出白天与夜读真显卡截图，第一次绝对尺子打分）→ 美术三件小道具试产（一天）。测试的 gate 脚本与灯光并行。
5. **截图基础设施** → 采纳真显卡：Playwright 连 Windows 侧 Chrome 的远程调试端口；连不上回退 swiftshader 只跑功能用例。与烘焙互斥加锁。
6. **第一个可玩版本的定义** → 五件事：走到书墙取一本书读到正文并放回；开关灯；走到桌前写一句并看到货币加一滴；走到商店买一盆花放进窗台；三个对焦站可进可出。画质不在验收里。
7. **打包** → 不引框架不变；允许一个几十行的 Python 拼接脚本把 ES 模块合成单文件，开发时直接开源文件。
